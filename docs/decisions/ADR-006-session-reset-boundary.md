# ADR-006：按会话边界安全地重新开始学习

- 状态：已接受
- 日期：2026-07-24
- 对应任务：[Task 008](https://github.com/ibka512/zhongri-v2/issues/8)

## 背景

Task006 可以恢复答题中、反馈中和已完成的学习会话，但用户无法从第一题重新体验。直接清空
整个 IndexedDB 会误删未来的其他课程或会话；只重置页面内存又会在刷新后恢复旧进度。
重新开始属于破坏性操作，还需要避免误触和“页面已重置但持久化删除失败”的状态分裂。

## 决策

1. `StudySessionRepositoryPort` 提供 `clearSession(sessionId)`，不暴露页面可调用的全库清除。
2. 清除范围固定为指定会话的 LearningEvent、Checkpoint、StudySessionState 和幂等记录。
3. Dexie 适配器在同一读写事务中清除四张表的对应记录；内存适配器遵守相同契约。
4. `StudyUseCase.restart` 负责先清除再创建初始会话，UI 不 import Infrastructure。
5. UI 在答题中和完成后都使用显式二次确认，并明确说明数据会删除且无法撤销。
6. 清除进行中禁用冲突操作；失败时保留原 `StudyUseCase`、页面快照和持久化进度，并显示
   可重试的原位错误。

## 影响

- 用户可以重复体验当前演示，不需要手工清理浏览器数据。
- 同一数据库中的其他 `sessionId` 不受影响。
- 旧幂等记录会随会话清除，因此重新答题可使用相同业务幂等键。
- 当前没有撤销能力；未来若引入归档、同步或审计，需要通过独立任务重新评估删除语义。

## 当前不包含

- 清除全部本地数据、账号数据设置或跨设备删除。
- 软删除、回收站、撤销、导入导出或备份。
- 真实课程/会话选择和历史记录管理。
- Schema 版本变化、v1 数据迁移、FSRS 或 AI。

## 验证

- 共享持久化契约证明只删除指定会话，并允许重新使用原幂等键。
- 故障注入证明清除失败不会出现部分删除。
- Application 测试证明重新开始回到第一题且事件为空。
- UI 测试覆盖取消、确认、完成后重开和失败保留进度。
- Format、Lint、TypeScript、Vitest、默认构建和 Pages 构建全部通过。
