# ADR-041：以浏览器内置朗读承载五十音最小切片

## 状态

已接受（2026-07-28，Task 019）

## 背景

Task 018 已由负责人在 GitHub Pages 验收，当前语言内容可以离线浏览。Phase 1 仍缺少日语最小的
假名辨认/听辨入口，但项目明确禁止在基础闭环稳定前接入远程音频、AI 或新的同步边界。浏览器
已经提供 `SpeechSynthesis`，适合用来验证语音能力检测、加载/失败反馈和可离线降级。

## 决策

- 新增 `/kana` 页面，只发布第一组基础平假名（あ行、か行共 10 个），以静态模块数据作为内容
  来源；不把这组练习伪装成完整五十音或 canonical 词库。
- 页面提供只存在于当前 React 会话的“辨认”和“听辨”两个模式。候选选择只产生本地反馈，不
  创建 LearningEvent，不写入 Dexie，不接入 LearnerProfile/FSRS。
- 通过 `SpeechSynthesisPort` 隔离浏览器 API。`BrowserSpeechSynthesis` 负责检测当前环境、使用
  `ja-JP` 与固定语速、取消上一段朗读并把 `onerror` 归一化为可显示错误；页面通过 composition
  callback 接收 port，不直接访问 `window` 的业务能力。
- `audioEnabled=false` 时不调用朗读能力，只展示设置关闭提示并提供 `/settings` 深链接；浏览器
  不支持或朗读失败时，文字辨认仍保持可用。
- 不新增设置 Schema、音频资源、网络请求、外部依赖或新的持久化表；后续完整五十音、片假名、
  IPA、发音评分和学习事实写入必须另行创建 Task/ADR。

## 影响

- 语音能力是可选增强，不会阻塞离线文字练习；浏览器差异通过显式状态呈现，便于负责人在 Pages
  上复测。
- 练习结果不进入学习闭环，因此当前切片不能产出掌握画像或复习调度证据；这项接线留给后续以
  Question/LearningEvent 为中心的专项任务。
- 未来若接入真实音频，必须保留本 Port 边界，并新增缓存、许可、失败回退和数据/隐私决策。

## 验收

1. `/kana` 的 10 个假名、两种模式、反馈和深链接通过 UI 测试。
2. adapter 在支持、缺失和朗读失败三种环境下通过单元测试，并验证 `ja-JP`、固定语速和取消
   上一段朗读。
3. 路由组合证明页面通过注入的 `loadUserSettings` / `loadKanaSpeech` 获取外部能力。
4. `npm run verify` 通过，且页面不引入网络请求或学习事实持久化。
