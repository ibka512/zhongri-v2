# ADR-039：以只读安全摘要承载设置与数据页首个切片

## 状态

已接受（2026-07-28，Task 017）

## 背景

Task 016 已把首次设置和本地 `LearnerSettings` 接入启动路径，但用户完成目标后还没有一个可回看的
设置与数据入口。MVP 需要让用户理解当前目标、旧版来源检测和本地优先边界；同时，备份、恢复和迁移
激活仍必须沿用现有的显式安全流程，不能因新增页面而扩大写入范围。

## 决策

- 新增 `/settings` 作为设置与数据安全摘要页，页面只消费 Application composition root 提供的
  `loadUserSettings` 与 `detectLegacyV1Data`。
- 页面展示已经保存的 `LearnerSettings`，修改动作统一回到 `/onboarding`，避免出现两套保存语义。
- v1 检测继续使用只读 `BrowserV1SourceStorage` 入口，只呈现三态结果，不创建快照、不写 v1、不激活
  staging；旧版备份继续从 `/migration-preview` 进入。
- 页面明确区分“本地设置已保存”“检测到旧来源”“隔离暂存等待验证”和“已激活迁移”，不把其中任何
  一项合并成“迁移完成”。
- 本切片不扩展设置 Schema、Dexie 表、主题持久化、备份导出/恢复、危险操作、音频或 AI。

## 影响

- `/settings` 成为 Task 016 之后的稳定回看入口，并为后续完整数据安全页保留深链接。
- 现有迁移预览页面继续承担文件选择、预检和显式暂存；本页只提供解释和导航。
- 后续若增加主题、减少动态、触觉、备份恢复或危险操作，必须以独立 Task/ADR 说明兼容性和失败边界。

## 验收

1. 已设置、无设置和读取失败状态均有可解释页面。
2. v1 检测三态不会阻断设置入口。
3. 测试证明页面只调用传入的 Application callbacks，不直接访问浏览器存储。
4. `npm run verify` 通过。
