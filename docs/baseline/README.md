# 产品基线目录

本目录是产品、迁移、架构和设计要求的仓库内基线。下一个 AI 不应依赖聊天记录或本机
Downloads 才能理解项目方向。

## 使用顺序

1. 先读 [`AGENTS.md`](../../AGENTS.md)、[`HANDOFF.md`](../development/HANDOFF.md) 和
   [`TASKS.md`](../TASKS.md)。
2. 再读本目录与当前 Task 直接相关的基线文档。
3. 再读 [`PROJECT_CONTEXT.md`](../PROJECT_CONTEXT.md)、架构文档和相关 ADR。
4. 当前实现事实以仓库代码和测试为准；产品目标、范围和迁移规则以本目录为准。

## 基线优先级

发生冲突时按以下顺序处理：

1. MVP 范围冻结与数据迁移规格：产品边界、上线门槛、数据保留和迁移安全。
2. v1 功能取舍与产品方向：功能归属、阶段安排和删除/合并决策。
3. 技术架构与 Design System：分层、Schema、UI 和平台约束。
4. Phase 0 工程初始化方案：工程初始化和早期契约。
5. PWA v1 PRD：旧产品事实和迁移来源，不自动恢复为 v2 新需求。

无法通过上述顺序解决的冲突必须新增 ADR，并在对应 Task 中记录；AI 不得静默选择一方。

## AI 执行红线

- 路线图只描述方向，不构成开发授权。
- 未出现在 `TASKS.md` 且没有任务合同的能力不能实现。
- 任何 Schema、迁移算法、FSRS 参数或数据语义变化都必须新增 ADR 和测试。
- 不把计划、推断、模型输出或历史聚合写成已发生的用户事实。
