# 钟日_v2_Design_System_设计规范

ZHONGRI · DESIGN SYSTEM

钟日 v2

Design System 设计规范

React + CSS / PWA 实现基线

视觉定位 苹果式秩序感 + 日系柔和气质 + 克制的学习游戏感。内容像纸，操作像玻璃，AI 像柔光。

设计目的

本规范用于指导钟日 v2 MVP 的真实网页组件、交互状态、无障碍、深色模式与动效实现。它不是概念稿，不授权新增页面、题型或产品能力。

版本：v1.0 · 2026-07-24

文档类型：实现级 UI 系统规范 / MVP 范围内

# 0. 使用说明与冻结边界

唯一设计目标 让用户更愿意每天完成语言学习。任何视觉、动效或组件变化都必须证明它能降低理解成本、增强反馈、维持注意力或建立信任。

## 0.1 设计系统的角色

| 本规范负责                                                                        | 本规范不负责                                                               |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 定义视觉令牌、材质层级、组件状态、页面布局、动效参数、无障碍与 CSS/PWA 落地约束。 | 不新增产品功能，不改变数据迁移规则，不设计数据库，不把 AI 变成聊天主界面。 |
| 把“内容像纸、操作像玻璃、AI 像柔光”转换为可审查的界面规则。                       | 不要求复制 iOS 控件，不使用 Material 组件外观拼装产品。                    |
| 覆盖 MVP 六个页面、两类答题渲染原语与音频模块。                                   | 不覆盖 ASR、实时语音、开放题、高级题型、账号同步、商业化和社区。           |

## 0.2 与既有产品决策的接口

- 主导航只有“今日、内容、设置”。首次设置仅在首次或重设目标时出现；学习页与结果页属于临时任务流。

- 五种 v1 学习模式不作为首页入口；视觉系统只为统一题目与训练策略提供状态，不重新制造模式宫格。

- LearningEvent 是行为事实，画像是聚合，FSRS 负责复习时点；界面不得把 AI 推断伪装成确定事实。

- MVP 固定使用“选择、文本输入”两类答题原语，音频作为组合模块；视觉丰富度不能诱导新增题型。

- 基础路径必须在 AI 不可用、网络离线或额度用尽时仍可完成。

- 迁移报告、备份恢复、回收站与历史 AI 对话归档属于设置与数据页，不扩张主导航。

## 0.3 内容目录

- 1. Design Token：颜色、字体、间距、圆角、阴影、动效与响应式基础。

- 2. 材质系统：内容纸面、交互玻璃与 AI 柔光的分层边界。

- 3. 组件系统：导航、按钮、AI Bubble、题目、答案、反馈与进度。

- 4. 页面规范：首次设置、今日首页、学习页、结果页、内容页、设置与数据页。

- 5. 答题界面重点规范：从出题到下一题的完整状态连续性。

- 6. 动效规范：目的、触发、时长、缓动、可关闭方式。

- 7. CSS / React / PWA 实现建议：令牌分层、组件边界、状态模型与 /ui-lab。

- 8. UI 审核清单：新增页面或组件的发布门槛。

# 1. Design Token

采用“基础值 → 语义角色 → 组件变量”三层模型。组件不得直接引用任意十六进制颜色或临时像素值。MVP 只提供固定的日间与暗色主题，不采用系统壁纸动态取色。

## 1.1 Token 命名与分层

| 层级      | 命名示例                                      | 职责                           | 规则                       |
| --------- | --------------------------------------------- | ------------------------------ | -------------------------- |
| Primitive | --zr-blue-600、--zr-space-4                   | 保存原始颜色、间距、时长等值。 | 只在主题与语义映射层使用。 |
| Semantic  | --zr-color-text-primary、--zr-surface-paper   | 表达内容含义与主题角色。       | 页面与组件优先引用此层。   |
| Component | --zr-button-primary-bg、--zr-ai-bubble-border | 处理组件局部组合与状态。       | 不得反向定义全局语义。     |

对比度基线 普通文字至少 4.5:1；大号或粗体文字至少 3:1；控件边界、焦点和表达状态的非文字图形至少 3:1。禁用状态虽可豁免，但仍应可辨认。

## 1.5 字体与排版

| 用途      | 推荐字体栈 / 策略                                        | 字号 / 行高            | 规则                                             |
| --------- | -------------------------------------------------------- | ---------------------- | ------------------------------------------------ |
| 中文      | system-ui → PingFang SC → Noto Sans SC → Microsoft YaHei | 正文 16/24             | 默认使用系统字体；长文不低于 16px。              |
| 日语      | Hiragino Sans → Yu Gothic UI → Noto Sans JP              | 正文 16/25             | 用 lang=ja 选择字形；假名/汉字学习焦点 28–40px。 |
| 英语      | system-ui → Segoe UI → Noto Sans                         | 正文 16/24             | 单词学习焦点 28–36px；长词允许换行。             |
| 音标 IPA  | Noto Sans → Doulos SIL / Charis SIL fallback             | 焦点 22–28 / 32–38     | 保留 / /、[ ] 与重音符号；不得用不完整图标字体。 |
| 数字      | 沿用 UI 字体；计时和进度启用 tabular-nums                | 标签 13/18；重点 24/30 | 倒计时不进入 MVP；预计时长不制造压迫。           |
| Ruby 注音 | 跟随日文字体                                             | 正文的 0.5–0.6em       | 颜色为次级文字；保持汉字与注音清晰对应。         |

### 排版阶梯

| Token   | 字号 / 行高 | 字重      | 字距     | 典型用途                               |
| ------- | ----------- | --------- | -------- | -------------------------------------- |
| display | 32 / 40     | 700       | -0.02em  | 首次设置标题、结果核心结论；少量使用。 |
| title-1 | 28 / 36     | 700       | -0.015em | 页面主标题。                           |
| title-2 | 22 / 30     | 650       | -0.01em  | 区块标题、今日计划标题。               |
| title-3 | 18 / 26     | 650       | 0        | 组件标题、反馈标题。                   |
| body-lg | 17 / 26     | 400 / 600 | 0        | 题目说明、关键解释。                   |
| body    | 16 / 24     | 400       | 0        | 默认正文、选项、输入。                 |
| body-sm | 14 / 20     | 400 / 600 | 0.005em  | 辅助说明、元数据。                     |

- 输入框文字不得低于 16px，避免 iOS Safari 聚焦时自动缩放。

- 字号放大到 200% 时不截断关键内容；标题允许换行，按钮文本优先扩高而非省略。

- 同一行混合中文、日语、英语时使用 lang 标记，不通过单独 span 强行切换任意品牌字体。

## 1.9 动效 Token

| Token           | 值                         | 用途                                 |
| --------------- | -------------------------- | ------------------------------------ |
| motion-instant  | 80ms                       | 触控按下、高频状态确认。             |
| motion-fast     | 120ms                      | 选项状态、图标切换、焦点变化。       |
| motion-base     | 180ms                      | 反馈展开、AI 小气泡、常规元素进入。  |
| motion-slow     | 240ms                      | Sheet、较大容器、页面级轻转场。      |
| motion-emphasis | 280ms（上限）              | 完成课程等低频重点反馈。             |
| ease-out        | cubic-bezier(.23,1,.32,1)  | 进入、按下回弹、反馈；默认 UI 缓动。 |
| ease-in-out     | cubic-bezier(.77,0,.175,1) | 屏内重排、进度移动。                 |

动效上限 高频学习操作越频繁，动画越短。下一题只做 120–160ms 的轻交叉淡化；键盘连续操作可直接切换。禁止 transition: all、scale(0)、过度弹跳与纯装饰循环。

# 2. 材质系统

材质不是装饰风格，而是信息层级。钟日只允许三种明确角色：内容纸面、交互玻璃、AI 柔光。每个区域先确定职责，再选择材质。

| 层级 | 材质     | 承载内容                                 | 视觉特征                      | 滚动关系                 |
| ---- | -------- | ---------------------------------------- | ----------------------------- | ------------------------ |
| L0   | 画布     | 页面环境与安全区。                       | 和纸白 / 深灰蓝，无纹理噪点。 | 随页面固定。             |
| L1   | 内容纸面 | 题目、单词、解释、列表、结果。           | 实色、高对比、少阴影。        | 正文滚动。               |
| L2   | 交互玻璃 | 底栏、浮动导航、音频、AI Bubble、Sheet。 | 半透明、模糊、亮边、阴影。    | 内容可从下方经过。       |
| L3   | 模态层   | 必须完成或确认的短任务。                 | 玻璃或实色 Sheet + scrim。    | 阻断背景操作并保留退出。 |

## 2.1 内容层：像纸

- 背景必须是实色 surface-paper；长文本、题目和解析不使用 backdrop-filter。

- 层级主要依靠排版、留白、分组标题和细边界，而不是每段套卡片。

- 同一页面以一个连续纸面为主；卡片只突出今日计划、结果总结或可独立操作的内容。

- 暗色纸面使用深灰蓝而非纯黑；文字不使用低透明白来模拟层级。

- 题目与答案之间保留稳定垂直间距，反馈出现后避免整体跳动。

## 2.2 交互层：Liquid Glass / 毛玻璃

| 参数 | 日间                  | 暗色                         | 回退                                         |
| ---- | --------------------- | ---------------------------- | -------------------------------------------- |
| 背景 | 白色约 72% 不透明     | 深灰蓝约 76% 不透明          | 不支持模糊时使用 surface-elevated。          |
| 模糊 | 18px，饱和度约 130%   | 18px，饱和度不提高或轻微降低 | prefers-reduced-transparency 时关闭。        |
| 边界 | 高光白边 + 柔和外阴影 | 约 12% 白边 + 较轻黑影       | prefers-contrast: more 时改实色 + 明确边框。 |
| 圆角 | 22–24px               | 22–24px                      | 不改变。                                     |
| 层数 | 同一位置最多一层玻璃  | 同左                         | 禁止玻璃叠玻璃。                             |

允许使用玻璃：

- 底部导航；学习页底部操作托盘；浮动返回/更多控制。

- AI Bubble；音频控制条；短操作 Sheet、Popover 和弹窗。

- 滚动后悬浮的顶部栏，仅当内容确实从其下方经过时。

禁止使用玻璃：

- 题目正文、答案选项、词条释义、例句、语法解释和长列表。

- 输入框文字承载面、迁移报告、备份内容与错误详情。

- 玻璃上的第二层玻璃、低对比彩色文字、忙碌图片背景上的细字。

- 只为了“高级感”而给普通卡片加模糊；不发生前后层关系时使用实色。

## 2.3 AI 层：像柔光

AI 柔光是存在感，不是大面积渐变。柔光只位于 AI 标记、Bubble 边缘或加载状态后方；消息主体仍是可读的实色 / 高不透明度容器。

| 元素     | 规范                                                                 |
| -------- | -------------------------------------------------------------------- |
| 核心标记 | 抽象柔光圆点或小型光团，16–24px；不使用卡通人物头像，不持续漂浮。    |
| 光晕     | AI glow 色，半径 24–40px，低透明；只作为装饰，不承载文字或状态。     |
| 消息主体 | AI container 实色或高不透明玻璃；必须显示“AI 外教”及触发原因/来源。  |
| 出现频率 | 默认每个学习区块最多主动出现一次；用户主动请求提示或解释不受此限制。 |
| 行为边界 | 不抢焦点、不遮题、不自动滚动用户位置、不在键盘弹出时覆盖输入区。     |
| 失败回退 | AI 不可用时显示“系统提示”或模板解释，不伪装成 AI 内容。              |

# 3. 组件系统

组件以可预测状态和组合为核心。所有组件必须提供日/暗主题、键盘焦点、触控目标、加载、错误、离线与减少动态行为。

## 3.1 Navigation

### 顶部栏 Top Bar

- 高度 52–56px；左侧返回或页面标题，右侧最多两个次要动作。

- 页面首屏可与内容同一纸面；滚动后若悬浮覆盖内容，才切换为玻璃材质。

- 标题单行优先，可在窄屏缩短而不是压缩返回按钮；学习页显示区块名而非重复产品名。

- 返回目标至少 44×44px；使用明确箭头与可访问名称，不只靠手势。

### 底部导航 Bottom Nav

| 项目   | 规则                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| 导航项 | 固定 3 项：今日、内容、设置。学习页和结果页不显示可跳走的完整底栏，可使用最小退出/暂停控制。 |
| 高度   | 56px + bottom safe area；每项至少 48px 高。                                                  |
| 材质   | 单层玻璃；不使用独立的三个悬浮卡片。                                                         |
| 图标   | 20–22px 单色线性图标 + 12–13px 标签；不要彩色方形底。                                        |
| 选中   | 品牌色图标与标签 + 低对比品牌容器或细顶部指示；颜色之外有形态/字重变化。                     |
| 键盘   | 按 DOM 顺序可访问；focus ring 不被圆角和 overflow 裁切。                                     |

## 3.2 Button

| 变体      | 视觉                                     | 使用场景                                               |
| --------- | ---------------------------------------- | ------------------------------------------------------ |
| Primary   | 琉璃蓝实色、白字；暗色为亮蓝底、深墨字。 | 每个视图最多一个主要动作，如“开始今日学习”“提交答案”。 |
| Secondary | 品牌浅容器或纸面 + 边界。                | 查看详情、再次练习、恢复备份等。                       |
| Tertiary  | 透明背景、品牌文字；按下有轻色面。       | 跳过、稍后、关闭说明。                                 |
| AI Action | AI 容器 + 鸢尾紫文字/边界。              | 查看提示、生成例句、需要 AI 解释。                     |
| Danger    | 错误色文字/边界，最终确认时才用实色。    | 删除、完全重置；必须与普通设置分区。                   |

| 状态          | 视觉与行为                                           | 反馈 / 动效                                       |
| ------------- | ---------------------------------------------------- | ------------------------------------------------- |
| default       | 高度默认 48px；标签居中，左右内距 20px。             | 无自动动画。                                      |
| pressed       | 整体 scale .97–.98；颜色进入 strong 角色。           | 80–120ms ease-out；触觉仅在用户开启且设备支持时。 |
| loading       | 锁定重复提交，保持原宽高；标签替换为进度与可读状态。 | 图标可旋转但不改变布局；超过 2s 显示原因/取消。   |
| success       | 短暂切换勾选与“已完成”，随后进入下一状态。           | 180ms；不弹跳、不撒花。                           |
| error         | 错误色边界 + 就地文本，按钮仍允许重试。              | 160ms 色彩/图标变化；不使用强烈摇晃。             |
| disabled      | 使用 muted 面与可辨文字；移除阴影。                  | 无按下反馈；必须说明不可用原因或满足条件。        |
| focus-visible | 双层焦点环，保持在组件外可见。                       | 即时出现；鼠标点击不强制显示。                    |

## 3.3 AI Bubble

定位 AI Bubble 是上下文辅助组件，不是聊天窗口。它只能解释当前学习、提供有限操作或展示个性化总结。

| 组成     | 规范                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 柔光标记 | 16–24px，位于标题前；加载时可缓慢一次性呼吸，不无限循环。                    |
| 来源行   | “AI 外教” + 触发原因，例如“基于本次错题”或“你请求了提示”；不得伪造历史数量。 |
| 正文     | 1–3 句为宜；复杂解释进入抽屉，不在 Bubble 塞长文。                           |
| 操作     | 最多两个按钮，主次明确；示例：[查看提示] [我再想想]。                        |
| 位置     | 移动端在题目/反馈之后、操作区之前；宽屏可放在 240–280px 侧栏。               |
| 可关闭   | 提供收起或忽略；收起后保留小型“AI 提示可用”入口。                            |
| 读屏     | 新提示 aria-live=polite；不自动移动焦点，用户展开后按阅读顺序访问。          |

| 状态      | 表现                                                       |
| --------- | ---------------------------------------------------------- |
| hidden    | 不占空间；不得在每题预留显眼空洞。                         |
| offer     | 短消息 + 1–2 操作，主体实色/高不透明玻璃。                 |
| loading   | 保持尺寸，显示“正在整理解释”；允许取消，超过阈值显示回退。 |
| response  | 显示结论、例句或解释；长内容可展开。                       |
| error     | 明确“暂时无法连接 AI”，提供系统解释或稍后再试。            |
| dismissed | 本题内不再主动弹出；用户仍可从提示按钮打开。               |

## 3.4 Question Container

| 区域          | 内容                          | 布局规则                                   |
| ------------- | ----------------------------- | ------------------------------------------ |
| A. 会话状态   | 区块名称、题号、轻量进度。    | 顶部固定或置于内容首部；不显示考试倒计时。 |
| B. 题目上下文 | 题型标签、必要说明、来源。    | 辅助文字，避免重复题干。                   |
| C. 题目焦点   | 单词、假名、IPA、句子或问题。 | 实色纸面；最大宽度 680–720px。             |
| D. 媒体       | TTS / 音频控制。              | 靠近它影响的题目；失败时提供文字替代。     |
| E. 作答区域   | 选择或文本输入。              | 选项间距 12px；输入与提交关系清晰。        |
| F. Feedback   | 对错、答案、解释、AI 入口。   | 原位展开；不遮挡当前答案。                 |
| G. 下一步     | 提交 / 下一题 / 完成区块。    | 底部操作托盘可用玻璃，但正文预留空间。     |

- 题目容器不是传统试卷卡片：页面只显示当前任务所需信息，避免题号、分数、计时器同时争抢。

- 反馈出现时保持题目和用户答案可见，帮助建立“答案 → 原因”的空间关系。

## 3.5 Answer Components

### 选择按钮

| 状态      | 规范                                                             |
| --------- | ---------------------------------------------------------------- |
| 默认      | 最小高度 52px，左对齐，14px 圆角；文字可换行，选项标记位宽固定。 |
| hover     | 仅桌面增强：轻微 surface-subtle；不移动位置。                    |
| selected  | 品牌浅容器 + 2px 品牌边界 + 明确选择标记。                       |
| correct   | 成功容器 + 勾选 + “正确”文本；保持用户选择可见。                 |
| incorrect | 错误容器 + 错误标记；同时标出正确答案，不能只把错误项染红。      |
| disabled  | 提交后其余选项不可再改，但文字与对比仍可读。                     |

### 文本输入

- 高度至少 52px，字体 16px；有明确标签或题目关系，不只用 placeholder。

- 输入中保持中性；在 IME composition 完成前不得触发提交，适配中文与日文输入。

- 提交后显示用户原始输入和规范化后的判定结果；拼错内容作为学习事实记录，但 UI 不公开技术字段。

- 错误说明放在输入框下方并预留最小空间，避免页面跳动；读屏使用适当的错误关联。

- 允许清空、重试或继续，但不在一次错误后清空用户答案。

### 音频按钮 / 控制条

| 元素     | 规范                                                                |
| -------- | ------------------------------------------------------------------- |
| 播放按钮 | 48–56px 触控目标，图标 + 可访问名称；按下立即进入 loading/playing。 |
| 播放状态 | 使用进度环、短波形或“播放中”标签；波形反映真实音频，不做装饰循环。  |
| 重听     | 与主播放共用同一按钮；重听次数记录但不用于羞辱或扣分。              |
| 语速     | 0.75× / 1× 等紧凑选择，置于 Popover 或辅助按钮；保持当前值可见。    |
| 失败     | 显示“音频暂不可用” + 重试；题目必须有可作答的回退或可跳过路径。     |
| 减少动态 | 停止波形位移动画，保留静态图标、进度文本与颜色状态。                |

## 3.6 Feedback

| 反馈        | 语气                 | 结构                                          | 禁止                               |
| ----------- | -------------------- | --------------------------------------------- | ---------------------------------- |
| 答对        | 平静、有成就感。     | 勾选 + “正确” + 1 句记忆强化；可选例句。      | 满屏绿色、夸张连击、随机赞美。     |
| 答错        | 中性、帮助理解。     | “先看区别” + 用户答案 + 正确答案 + 简短原因。 | 叉号轰炸、震屏、惩罚文案。         |
| 模糊 / 忘记 | 承认真实状态。       | 记录自评并说明“会安排复习”。                  | 直接判定失败或把三维掌握全部清零。 |
| 提示已用    | 透明说明。           | 显示提示内容并保留提示标记。                  | 隐藏提示使用或制造羞耻感。         |
| AI 解释     | 明确来源与不确定性。 | AI 外教标签 + 针对性解释 + 可关闭。           | 把 AI 输出当作程序确定事实。       |

## 3.7 Progress

| 类型     | 表现                                                    | 原则                                          |
| -------- | ------------------------------------------------------- | --------------------------------------------- |
| 今日进度 | 水平进度条 + 已完成/总量；可按区块分段。                | 不做金币、经验条或不可解释等级。              |
| 题目进度 | “3 / 8” + 4px 细轨；下一题时平滑更新。                  | 不显示倒计时，不制造考试压力。                |
| 学习时间 | 预计剩余分钟 / 今日已学习分钟。                         | 使用近似值；不要伪装精确。                    |
| 掌握变化 | “更稳定 / 需要再见一次 / 已进入复习”等文字 + 小幅变化。 | 不只显示抽象百分比；FSRS 内部参数不直接暴露。 |
| 连续表现 | “连续答对 5 题”等短期反馈。                             | 只在有帮助时出现，不转化为强迫性连胜系统。    |

# 4. MVP 六页面设计规范

六个页面共享 App Shell、语义色彩与组件状态，但每页只保留完成主任务所需的信息。下面的“空状态”包括数据为空、首次使用或筛选为空；“错误状态”必须提供恢复路径。

## 4.1 首次设置

# 5. 答题界面重点规范

体验目标 像自然的系统任务，而不是传统考试：一次只做一件事，用户每一步都知道系统已收到操作、为什么得到反馈、接下来会发生什么。

## 5.1 题目出现

- 进入学习页先稳定显示会话标题和进度，再呈现题目；不让按钮、题干和 AI 同时抢入场。

- 题目使用 120–160ms opacity + 4–8px 内的轻位移；高频连续答题可只淡化。

- 题干加载失败时不保留空骨架超过必要时间；立即给出重试、换题或退出路径。

- 切题后焦点放在题目标题或首个可交互答案，依据输入方式决定；不得把读屏焦点丢到页面顶部。

## 5.2 选项反馈

| 阶段   | 界面表现                                   | 数据与交互                        |
| ------ | ------------------------------------------ | --------------------------------- |
| 未选择 | 中性纸面选项，hover 仅增强。               | 允许键盘方向键/Tab 与触控。       |
| 已选择 | 品牌浅容器、明确选中标记；提交按钮可用。   | 尚未判题，可更改选择。            |
| 提交中 | 锁定重复提交，保留选中项。                 | 记录耗时到提交时点；反馈不先猜。  |
| 答对   | 选中项转成功状态，显示“正确”。             | 程序判定；更新事件后允许下一题。  |
| 答错   | 用户选择显示错误状态，正确项显示成功状态。 | 记录错误选项；Feedback 解释差异。 |

## 5.3 输入反馈

- 输入时不预判对错；可显示字符要求、语言键盘提示或规范化说明。

- 提交后不替换用户原文，正确答案在下方并列展示；差异高亮仅标关键字符。

- 日语 IME 组合期间 Enter 只确认候选，不提交题目；组合结束后才响应提交。

- 轻微格式差异若被程序接受，应明确“答案正确，已自动忽略空格/大小写”等，建立判题信任。

## 5.4 AI 提示出现

| 触发                  | 位置与内容                                                      | 禁止                           |
| --------------------- | --------------------------------------------------------------- | ------------------------------ |
| 用户点“需要提示”      | 在答案区下方展开短 Bubble；提供一个可执行提示，不直接泄露答案。 | 弹出全屏聊天或把焦点移走。     |
| 重复错项 / 高价值解释 | 判题反馈后出现“需要 AI 解释吗？”；用户确认后调用。              | 每道错题自动请求模型。         |
| 进度鼓励              | 优先使用规则模板和内联文字。                                    | 把普通鼓励伪装成 AI。          |
| AI 失败               | 原位显示失败与系统解释；按钮可重试。                            | 关闭整个答题页或清空现有反馈。 |

## 5.5 音频控制

- 按下播放后 80ms 内出现视觉状态，即使音频仍在缓冲；缓冲与播放图标必须区分。

- 重听使用同一播放按钮，不新增一排操作；速度选项位于靠近按钮的 Popover。

- 播放中进度与声音实际同步；页面切到下一题时停止旧音频并重置控制。

- 后台/锁屏恢复后状态必须与真实播放器一致，不能显示“播放中”而实际静音。

## 5.6 下一题过渡

- 用户提交，答案控件立即进入 submitting，阻止重复提交。

- 程序写入判定与 LearningEvent；当前题目保持可见。

- Feedback 原位展开，进度暂不前移，给用户建立因果。

- 用户点“下一题”后，当前内容 120–160ms 淡出；进度移动。

- 下一题从相同内容锚点出现；页面滚动到题目起点，底部操作保持空间连续。

连续性规则 状态顺序固定为 idle → answering → submitting → correct / incorrect → ready-next。不得跳过 submitting，也不得在 Feedback 出现前替换整页。

# 6. 动效规范

每个动效必须有目的、触发、时长、缓动与关闭方式。动效审查先问“是否需要”，再问“如何做”。

| 动效           | 目的                               | 触发                       | 时长      | 缓动              | 可关闭 / 降级                                   |
| -------------- | ---------------------------------- | -------------------------- | --------- | ----------------- | ----------------------------------------------- |
| 页面进入       | 建立页面层级，不制造跳切。         | 非高频页面导航。           | 180–240ms | ease-out          | 减少动态：80–120ms 淡化；键盘高频导航可无动画。 |
| 题目切换       | 说明同一学习流内的内容替换。       | 点击下一题。               | 120–160ms | ease-out          | 减少动态：即时或 80ms 淡化；无位移。            |
| 答案按下       | 确认系统收到触控。                 | pointer down。             | 80–120ms  | ease-out          | 可随减少动态移除缩放，保留色面。                |
| 答题反馈       | 连接答案与结果。                   | 判题完成。                 | 160–200ms | ease-in-out       | 减少动态：即时色彩 + 文本；不展开位移。         |
| AI Bubble 展开 | 标明提示来自当前题目。             | 用户请求或区块级提示。     | 180–220ms | ease-out          | 减少动态：短淡化；关闭 blur/scale。             |
| 音频播放       | 显示缓冲、播放和结束。             | 播放状态变化。             | 80–160ms  | ease-out / linear | 减少动态：静态图标 + 时间文本；无波形位移。     |
| 完成课程       | 确认任务结束并转入总结。           | 最后一题完成。             | 240–280ms | ease-in-out       | 减少动态：结果页直接出现；无庆祝运动。          |
| 错误提示       | 把注意力引向可修复位置。           | 验证或保存失败。           | 120–160ms | ease-out          | 保留颜色、图标、文字；禁止强摇晃。              |
| Sheet / 弹窗   | 表达从触发点到临时任务的空间关系。 | 打开设置、解释、迁移报告。 | 220–280ms | ease-sheet        | 减少动态：120ms 淡化；减少透明：实色面。        |

## 6.1 动效审查规则

- 高频：题目切换、选项点击、播放按钮，只允许短反馈；不得每次弹跳或大位移。

- 偶发：Sheet、迁移报告、AI 解释，可使用标准转场，但不超过 280ms。

- 低频：首次设置、完成课程，可有一点情绪，但钟日不使用粒子、彩带、金币和连续光效。

- 进入使用 ease-out；屏内重排用 ease-in-out；真实连续量用 linear。禁止为 UI 进入使用 ease-in。

- 优先动画 transform 和 opacity；避免 width、height、margin、padding 引发布局抖动。

- 交互可被再次触发时必须可中断；从当前屏幕状态继续，不等待上一动画结束。

- 视觉、触觉、声音反馈必须指向同一事件；关闭触觉或声音后仍有完整视觉与文本反馈。

## 6.2 Reduced Motion / Transparency / Contrast

| 用户偏好                     | 系统行为                                                         |
| ---------------------------- | ---------------------------------------------------------------- |
| prefers-reduced-motion       | 移除位移、弹簧、缩放与视差；保留 80–120ms 透明度或即时状态变化。 |
| 应用内减少动态               | 与系统偏好取更严格值；设置立即生效并持久化。                     |
| prefers-reduced-transparency | 玻璃改为高不透明或实色，关闭 backdrop-filter。                   |
| prefers-contrast: more       | 语义面更接近实色，边界加深，焦点环更明确，减少半透明文字。       |
| 触觉关闭                     | 不调用震动；视觉/文字不变。                                      |
| 声音关闭                     | 不自动播放；音频题提供明确的手动播放与可用回退。                 |

## 7.3 交互状态模型

| 对象      | 状态序列                                                       | 关键规则                                   |
| --------- | -------------------------------------------------------------- | ------------------------------------------ |
| 题目      | idle → answering → submitting → correct/incorrect → ready-next | 状态单向推进；退出/恢复保存当前位置。      |
| AI        | hidden → offer → loading → response/error → dismissed          | 错误不影响固定题；dismissed 不再主动出现。 |
| 音频      | idle → loading → playing → paused/ended/error                  | UI 必须反映真实播放器状态。                |
| 迁移/备份 | idle → checking → processing → success/error                   | 处理中防重复；失败保留现有数据和报告。     |
| 按钮      | default → pressed → loading → success/error → default/disabled | 保持尺寸，不发生标签导致的布局跳动。       |

## 7.4 PWA 与平台适配

- 使用系统字体为默认，避免首屏依赖远程字体；若后续打包 Noto，必须有离线缓存与 font-display 策略。

- 所有固定底栏、Sheet 和学习操作托盘适配安全区域；软键盘出现时不能遮挡输入与提交。

- backdrop-filter 必须有实色回退；Safari 模糊性能不稳定时降低模糊半径而非牺牲滚动。

- 离线状态使用非阻断提示：基础复习、内置题目、已缓存音频与数据操作继续；AI 操作明确不可用。

- 长词库采用连续列表和按需渲染；视觉状态不能依赖列表全部在 DOM 中。

- 图标使用统一 SVG 集，20/24px 视觉尺寸、currentColor；不混用 emoji 与多个图标风格。

## 7.5 /ui-lab 作为实现验收面

/ui-lab 不增加用户功能，它是开发内部页面。每个组件在进入真实页面前必须在以下矩阵中验证：

| 维度 | 必须覆盖                                                                 |
| ---- | ------------------------------------------------------------------------ |
| 主题 | 日间、暗色、提高对比、减少透明。                                         |
| 交互 | 默认、hover、focus-visible、pressed、loading、success、error、disabled。 |
| 输入 | 触控、键盘、鼠标、日文 IME、长文本、200% 字体。                          |
| 网络 | 在线、离线、慢速、AI 超时、音频失败。                                    |
| 内容 | 中/日/英/IPA、长单词、多行选项、空数据、真实错误信息。                   |
| 动效 | 标准、减少动态；60fps 观察与慢放检查。                                   |
| 设备 | 窄屏手机、宽屏手机、平板/桌面、安全区域与软键盘。                        |

# 8. UI 审核清单

每次新增页面、组件或状态前逐项检查。任何“否”都需要修正或记录明确例外。

## 信息层级与产品边界

- □ 首屏最重要内容是否一眼可见，主要动作是否唯一？

- □ 是否仍围绕“今日学习”闭环，而非新增模式入口或页面？

- □ 控件是否靠近它影响的内容，用户是否知道当前位置与退出方式？

- □ 是否避免用多张圆角卡片代替真正的信息分组？

- □ 是否没有把 AI 做成聊天框或任意布局生成器？

## 钟日视觉气质

- □ 内容是否使用高可读实色纸面？

- □ 玻璃是否只出现在真实浮动交互层，且没有玻璃叠玻璃？

- □ AI 是否像柔光但不遮题、不抢焦点、不持续闪动？

- □ 色彩是否保持和纸白、浅青、琉璃蓝、鸢尾紫 / 深灰蓝、墨色？

- □ 游戏感是否只来自进度、反馈和掌握变化，而非金币、宝箱、幼稚卡通？

## 状态与反馈

- □ default、pressed、loading、success、error、disabled 是否完整？

- □ 重要操作是否在按下时立即给出反馈，提交后是否保留因果关系？

- □ 错误是否说明发生了什么、如何恢复，并保留用户输入？

- □ 状态是否同时使用文字/图标/形态，而非只靠颜色？

- □ AI、音频、迁移或离线失败是否有不阻断核心闭环的回退？

## 无障碍与触控

- □ 普通文字是否达到 4.5:1，控件/焦点是否达到 3:1？

- □ 重要触控目标是否至少 48×48px，绝对不低于 44×44px？

- □ 所有操作是否可键盘访问，focus-visible 是否清晰且不被遮挡？

- □ 读屏名称、标题结构、错误关联与 aria-live 是否准确？

- □ 200% 字体、长翻译、日语/英语/IPA 是否不截断？

## 暗色与平台

- □ 暗色是否使用深灰蓝/墨色而非纯黑，并保持语义层级？

- □ 安全区域、软键盘、横竖屏与 PWA 独立窗口是否验证？

- □ 玻璃不支持或减少透明时是否有实色回退？

- □ 离线时是否明确哪些可用，AI 不可用是否不妨碍复习？

- □ 设置页是否使用克制的小型单色图标，而非拥挤彩色图标底？

## 动效质量

- □ 每个动画是否能回答“为什么需要”？

- □ 高频操作是否短于 160ms，偶发转场是否不超过 280ms？

- □ 是否避免 transition: all、ease-in 进入、scale(0)、过度弹跳和无限循环？

- □ 动画是否可中断，并只优先使用 transform / opacity？

- □ prefers-reduced-motion 是否有等价但更平静的反馈？

## 避免 AI 生成感

- □ 是否避免到处渐变、毛玻璃、发光描边与随机装饰？

- □ 图标、圆角、阴影、间距和文案是否来自统一 Token？

- □ 是否避免泛化标题、占位式统计与不存在的用户历史？

- □ AI 内容是否有来源标签、边界和失败状态？

- □ 界面是否像可长期使用的工具，而不是一次性展示稿？

## 8.1 发布门槛

Definition of Done 新页面或组件只有在 /ui-lab 中通过主题、状态、键盘、触控、读屏、离线、减少动态、长文本与窄屏检查，并证明没有扩大 MVP 范围后，才能进入真实产品。

# 附录 B：最终设计结论

钟日 v2 的界面 以连续的纸面承载学习内容，以少量玻璃层承载浮动操作，以明确来源的柔光 AI 提供上下文帮助。排版、留白、状态和反馈构成高级感；题型数量、聊天界面、渐变、卡片和动画数量不构成高级感。

- 用户每天只需要回答：今天学什么、现在做什么、刚才发生了什么、下一次会如何调整。

- 设计系统的每条规则都应帮助用户更快理解、更安心作答、更愿意完成今天的学习。

- 当视觉表达与学习清晰度冲突时，清晰度优先；当 AI 表达与系统可靠性冲突时，可靠性优先。
