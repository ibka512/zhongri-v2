# 0. 范围冻结摘要

本文件不是完整产品愿景清单，而是第一版的交付边界。任何未明确列入“必须功能”的能力，默认不进入 MVP。

| 冻结项 | MVP 决策                                                      | 不做什么                                 |
| ------ | ------------------------------------------------------------- | ---------------------------------------- |
| 入口   | 首页只有“今日学习”主路径，专项训练作为计划区块或次级入口。    | 不恢复 v1 五种模式宫格。                 |
| 个性化 | 规则搭骨架，AI 在固定边界内选内容、生成题目和解释。           | 不让 AI 自由编排前端、自由决定全部课程。 |
| 题型   | 只实现选择与文本输入两类渲染原语，音频作为可组合提示。        | 不为每个题型写一套独立页面。             |
| 数据   | LearningEvent 记事实，简版画像做聚合，FSRS 负责长期复习时点。 | 不把 AI 推断直接写成用户事实。           |
| 语言   | 日语与英语共用同一学习引擎；五十音与 IPA 只做基础训练切片。   | 不在 MVP 建两套平行产品。                |
| 语音   | 仅 TTS、播放、重听与语速控制。                                | 不做 ASR、发音评分或实时语音外教。       |
| 账户   | 本地优先、可备份、可迁移。                                    | 不做账号体系与跨设备同步。               |

MVP 发布边界 Phase 0—2 构成可验证的 MVP；Phase 3 是验证成立后的扩展，不得作为第一版延期理由。

## 冻结时的非目标

- 不证明“钟日能教完一门语言”，只证明个性化每日学习闭环有价值。

- 不追求题型数量、内容总量或 AI 对话时长。

- 不做社区、排行榜、金币、宝箱等增长或重游戏化系统。

- 不建设自有模型、完整云同步与商业化后台。

- 不重新解释或改写既有 v1 迁移规则；迁移实现以现有规格为准。

# 1. MVP 产品目标

## 一个核心目标

核心目标 验证用户是否愿意反复完成由系统基于真实学习行为调整的每日学习计划，并感知到内容“更相关、少选择、能接着学”。

## 三个辅助目标

| 辅助目标             | 第一版要证明的事实                                                              | 不要求证明                         |
| -------------------- | ------------------------------------------------------------------------------- | ---------------------------------- |
| 1. 数据闭环可运行    | 一次作答能形成 LearningEvent，汇总成简版薄弱点，并影响下一次计划。              | 不要求复杂能力模型或机器学习画像。 |
| 2. AI 内容可控可用   | AI 能输出通过 Schema 校验的少量题目、例句或解释，并有缓存与规则回退。           | 不要求所有题目都由 AI 生成。       |
| 3. v1 用户可安全过渡 | 核心词库、用户词、FSRS 连续性与历史资产按既有迁移规格保留，迁移可报告、可恢复。 | 不要求每个旧页面和交互原样复刻。   |

## 验证信号

首轮小规模试用只观察以下信号，不以“AI 看起来聪明”作为成功标准：

- 用户能在不选择旧模式的情况下理解并开始今日课程。

- 用户完成后能看懂“今天练了什么、为什么出现、下一次会如何调整”。

- 连续使用时，待复习、近期错项和基础薄弱点确实进入后续课程。

- AI 失败、离线或额度用尽时，基础复习闭环仍可完成。

# 2. MVP 用户闭环

第一版闭环固定为八步。首页与学习页围绕这条路径设计，其他能力不得打断主流程。

| 步骤            | 用户看到 / 操作                                     | 系统行为                                                                          | MVP 简化                             |
| --------------- | --------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------ |
| 1. 第一次打开   | 选择日语或英语，查看简短定位说明。                  | 检测是否存在 v1 数据；建立本地学习者配置。                                        | 不注册账号，不做冗长测评。           |
| 2. 设置目标     | 选择每日 5 / 10 / 15 分钟、学习重点与是否开启声音。 | 转换为新内容上限、复习上限和音频偏好。                                            | 等级只做粗粒度自选，可随时修改。     |
| 3. 生成今日学习 | 首页看到预计时间、待复习、薄弱点与“继续学习”。      | 规则先装入 FSRS 到期项，再装入近期错项和少量新内容；AI 只在限额内建议内容与难度。 | 无 AI 时使用稳定规则计划。           |
| 4. 完成课程区块 | 按顺序进入复习、薄弱点、基础训练或新内容。          | 每个区块调用同一学习会话引擎。                                                    | 用户可跳过单题，但不需先选训练模式。 |
| 5. 答题         | 在固定的选择或输入界面作答；音频题可重听。          | 程序确定性判题，记录答案、耗时、提示、重听和跳过。                                | 开放式题不进入 MVP。                 |
| 6. 获得反馈     | 立即看到对错、简短解释、例句或“需要 AI 解释”。      | 模板负责常规反馈；高价值错题可调用 AI。                                           | 不每题调用模型，不弹频繁聊天气泡。   |
| 7. 完成总结     | 结果页显示完成量、错项、掌握变化与下一步。          | 写入会话摘要；更新简版画像与 FSRS。                                               | 鼓励文案优先使用规则模板。           |
| 8. 下一次调整   | 下次打开时看到新的待复习和薄弱点安排。              | 读取聚合画像而非全量历史，重新生成今日计划。                                      | 不把全部 LearningEvent 发送给 AI。   |

闭环成立条件 第 8 步必须能够由第 5—7 步的真实数据解释。若后续计划与用户行为无关，即使 AI 能聊天，MVP 也不成立。

# 3. MVP 必须功能

严格冻结为九个产品能力。它们可以分阶段完成，但 Phase 2 结束时必须全部满足。

| 必须功能                    | 为什么必须存在                                      | 用户价值                               | 复杂度 | 对核心闭环                     |
| --------------------------- | --------------------------------------------------- | -------------------------------------- | ------ | ------------------------------ |
| 1. 轻量首次设置             | 今日计划需要语言、时间和声音偏好。                  | 第一次打开即可获得合适长度的课程。     | 低     | 起点；缺失会让计划无边界。     |
| 2. v1 迁移与内容连续性      | 既有词库、用户词、FSRS 和历史资产是实际用户的基础。 | 升级不丢数据，也不必从零开始。         | 高     | 是可信上线的前提。             |
| 3. 今日学习首页             | 新版必须从“选模式”转向“系统安排”。                  | 减少决策成本，知道今天做什么、要多久。 | 中     | 主入口与调度面。               |
| 4. 统一学习会话             | 所有课程区块必须共享进度、跳过、反馈和退出恢复。    | 体验连续，不因题型切换迷路。           | 中     | 承载完整答题路径。             |
| 5. 最小题目渲染器           | 结构化题目必须落进可控 UI。                         | 题目稳定、可读、可预测。               | 中     | AI 内容进入产品的安全闸门。    |
| 6. LearningEvent 与简版画像 | 个性化必须建立在真实行为而非最终掌握标签上。        | 错项、迟疑、提示依赖会影响后续练习。   | 高     | 连接作答与下一次调整。         |
| 7. FSRS 复习调度            | 长期记忆需要稳定、确定性的到期时间。                | 该复习的内容不会被 AI 新题淹没。       | 中     | 提供每日计划的复习骨架。       |
| 8. 受约束 AI 能力           | 产品需要验证 AI 是否能提高相关性与解释价值。        | 获得贴合错项的题目、例句和解释。       | 高     | 增强闭环；不得成为单点故障。   |
| 9. 基础训练切片与音频       | 日语五十音、英语 IPA 和 TTS 是两种语言的基础入口。  | 能练辨认、输入与听音，而非只背词义。   | 中     | 补充薄弱点区块，共用同一引擎。 |

## 必须功能的内部边界

| 能力     | MVP 包含                                                                    | 明确排除                                         |
| -------- | --------------------------------------------------------------------------- | ------------------------------------------------ |
| 今日计划 | 到期复习 + 近期错项 + 基础薄弱点 + 少量新内容；预计时间；继续学习。         | 复杂周计划、长期课程地图、AI 自由重排全部内容。  |
| 简版画像 | 近期错项、易混淆项、平均用时、提示依赖、重听倾向、近期趋势。                | 精细 CEFR/JLPT 能力诊断、预测分数、人格化标签。  |
| 五十音   | 平假名、片假名、浊音、半浊音、拗音的辨认、听辨与输入；促音/长音以词例出现。 | 复杂动画、手写识别、完整书写评分、独立闯关地图。 |
| IPA      | 基础元辅音、双元音、音素辨认、听音选择与少量高频混淆组。                    | 连读、弱读、语调、发音评分、完整口语课程。       |
| TTS      | 单词/句子播放、重复播放、基础语速选择。                                     | 录音、波形编辑、声音克隆、实时对话。             |

# 4. MVP 延后功能

延后不等于否定，而是避免这些能力成为核心闭环上线的前置依赖。

## 第二阶段：闭环稳定后的扩展

| 功能                       | 延后原因                                           | 进入条件                                  |
| -------------------------- | -------------------------------------------------- | ----------------------------------------- |
| 句子排序、配对、独立听写题 | 增加交互与校验分支，但对验证首个闭环不是必要条件。 | 选择/输入原语稳定，事件字段能覆盖新交互。 |
| 语法填空与轻量语法标签     | 需要可靠语法内容来源和错误归因。                   | 基础题目质量、校验与内容审核流程稳定。    |
| 开放式造句与翻译           | 需要 AI 判分、置信度、申诉与多答案处理。           | AI 解释质量可控，能保存结构化评分依据。   |
| 更完整的 AI 学习总结       | 每次生成会增加成本，且模板总结已能完成基础反馈。   | 证明用户会阅读并使用个性化总结。          |
| 更深的五十音 / IPA 课程    | 内容制作量大于引擎开发量。                         | 基础训练切片有真实使用与薄弱点数据。      |

## 第三阶段：语音与云能力

| 功能                 | 为什么不进 MVP                                       | 主要前置                                   |
| -------------------- | ---------------------------------------------------- | ------------------------------------------ |
| ASR 跟读与语音回答   | 设备兼容、隐私、噪声和识别结果解释都会扩大测试矩阵。 | TTS/听力闭环稳定；明确音频授权与保存策略。 |
| 发音反馈             | ASR 文本正确不等于发音评分可靠，需要音素级能力。     | 可解释的发音评分服务与人工抽检。           |
| 账号与跨设备同步     | 引入身份、冲突合并、服务端存储和隐私合规。           | 本地数据模型与迁移版本稳定；确有多端需求。 |
| 复杂语法系统         | 知识图谱、先修关系和内容标注工作量大。               | 语法题有稳定内容来源和足够使用数据。       |
| 高级题型与自适应难度 | 会成倍增加题目 Schema、渲染与测试组合。              | 核心题型指标和难度标尺稳定。               |

## 未来版本：验证商业与平台能力后再做

| 功能               | 延后决策                                                                    |
| ------------------ | --------------------------------------------------------------------------- |
| 实时语音 AI 外教   | 不进入 MVP 或第三阶段的硬承诺；只有在异步 AI 外教与语音练习均被验证后立项。 |
| 自建模型服务器     | 第三方 API 足以验证价值；自建会把产品风险转成模型运维与容量风险。           |
| 社区功能           | 与个性化学习闭环无直接因果，且带来审核、关系链和内容治理成本。              |
| 商业化系统         | 第一版只允许保留调用额度与成本统计，不建设订阅、支付、权益和定价系统。      |
| 完整课程商城 / UGC | 需要内容供给、版权与审核体系，不属于个人开发者首版。                        |

# 5. MVP 页面范围

MVP 只保留六个页面级容器。词条详情、AI 解释、提示和迁移报告使用抽屉或弹层，不再扩张主导航。

| 页面          | 必须性                           | 核心内容                                                               | 不在该页做                               |
| ------------- | -------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------- |
| 1. 首次设置   | 必须；仅首次或重设目标时出现。   | 语言、每日时长、粗粒度重点、声音偏好、v1 数据检测。                    | 账号注册、长问卷、完整分级测试。         |
| 2. 今日首页   | 必须；唯一主入口。               | 今日计划、预计时间、待复习、薄弱点、继续学习、最近趋势。               | 五种模式宫格、社交动态、复杂仪表盘。     |
| 3. 学习页     | 必须；合并课程、答题和即时反馈。 | 区块进度、固定题目 UI、音频、提示、跳过、简短解释。                    | 聊天式出题、独立题型页面、频繁 AI 气泡。 |
| 4. 结果页     | 必须。                           | 完成量、错项、掌握变化、下一次调整、继续或结束。                       | 复杂图表、分享海报、排名。               |
| 5. 内容页     | 必须但保持轻量。                 | 内置词、用户词、收藏/文件夹入口、搜索与词条详情。                      | 多层内容运营、完整课程商城。             |
| 6. 设置与数据 | 必须。                           | 学习目标、语言、声音、深色/减少动态、备份恢复、迁移报告、AI 额度状态。 | 支付、账号中心、开发者调参面板。         |

## 不单独建页的能力

| 能力         | MVP 归属                                                                |
| ------------ | ----------------------------------------------------------------------- |
| AI 外教      | 学习页中的按需解释 / 例句抽屉；结果页中的个性化总结。自由聊天入口延后。 |
| 错题本       | 由 LearningEvent 派生为“薄弱点 / 近期错项”筛选，不做独立数据孤岛。      |
| 五十音 / IPA | 作为今日计划中的基础训练区块，并可从内容页进入轻量专项。                |
| FSRS         | 后台调度能力；用户只看到待复习数量和到期提示。                          |
| v1 五种模式  | 变成计划可调用的训练策略，不作为主导航页面。                            |
| AI 历史对话  | 迁移后只读归档可从设置与数据进入；不作为主学习入口。                    |

# 6. MVP 题型范围

实现原则 产品上可呈现五类首批题目，但工程上只实现“选择”和“文本输入”两类渲染原语；音频是可组合提示模块。这样既覆盖两种语言的基础训练，又避免题型组件爆炸。

| 首批题型      | 选择理由                                                             | 底层复用            | MVP 判题                                   |
| ------------- | -------------------------------------------------------------------- | ------------------- | ------------------------------------------ |
| 单选题        | 覆盖词义、语境、易混淆项和大部分诊断题，是结构化出题的最低成本入口。 | 选择原语            | 程序按标准答案判定。                       |
| 拼写 / 输入题 | 覆盖英语拼写、日语假名输入，也能记录具体拼错内容。                   | 文本输入原语        | 程序做规范化后精确判定；可显示可接受答案。 |
| 听力选择题    | 验证 TTS、重听事件和声音—意义关联，不需要 ASR。                      | 音频模块 + 选择原语 | 程序判定选项。                             |
| 假名辨认题    | 满足五十音基础训练，并能记录 シ/ツ、ソ/ン 等混淆组。                 | 选择或输入原语      | 程序判定字符 / 读音映射。                  |
| 音标辨认题    | 满足 IPA 基础和 /ɪ/—/iː/ 等音素混淆训练。                            | 音频模块 + 选择原语 | 程序判定音素或单词选项。                   |

## 明确延后的题型

| 题型           | 阶段          | 原因                                                         |
| -------------- | ------------- | ------------------------------------------------------------ |
| 独立听写题     | 第二阶段      | 可先用“音频 + 输入”组合验证；稳定后再增加专属交互和容错。    |
| 句子排序       | 第二阶段      | 需要拖拽、键盘可访问性和多种正确顺序处理。                   |
| 配对题         | 第二阶段      | 移动端布局、状态同步和无障碍成本较高。                       |
| 语法题         | 第二 / 三阶段 | 先从填空开始；复杂语法系统不进 MVP。                         |
| 造句与开放回答 | 第二阶段以后  | 依赖 AI 判分、置信度和多答案解释，不适合作为首版确定性闭环。 |

# 7. MVP AI 能力范围

AI 是受约束的课程增强器，不是运行时的唯一老师。程序必须拥有可解释、可离线完成的基础路径。

| 任务       | 程序 / 规则负责                                         | AI 负责                                            | 失败时回退               |
| ---------- | ------------------------------------------------------- | -------------------------------------------------- | ------------------------ |
| 今日计划   | FSRS 到期项优先、区块配额、时长预算、新内容上限。       | 依据薄弱点摘要建议语境、干扰项、难度与区块内顺序。 | 完全使用规则计划。       |
| 结构化出题 | 候选知识点、Schema、校验、去重、答案合法性、题型渲染。  | 为指定知识点生成受限 JSON 题目、例句和干扰项。     | 使用内置题目或模板变体。 |
| 答案判断   | 所有 MVP 固定答案题的规范化与判定。                     | MVP 不参与固定答案裁决。                           | 无须回退。               |
| 错误解释   | 常见错误模板、正确答案、基础词条信息。                  | 用户点选或高价值重复错项时生成针对性解释。         | 显示模板解释与例句。     |
| 反馈与鼓励 | 进度、剩余题数、连对、用时与普通鼓励模板。              | 复杂语法提示、个性化总结或新例句。                 | 显示规则总结。           |
| 用户画像   | 从 LearningEvent 聚合近期错项、速度、提示和重听等指标。 | 读取摘要并提出训练建议；不得改写原始事件。         | 继续使用规则薄弱点排序。 |

## AI 调用冻结规则

- AI 输入只包含当前任务所需的词条、规则和画像摘要，不发送全量历史。

- AI 输出必须符合版本化 Question Schema；未通过校验的内容不得进入答题页。

- 题目按小批量生成并缓存；相同内容优先复用，禁止每题临时请求。

- 每次调用记录用途、耗时、成本估算、模型结果状态和回退原因，但不把模型推断当成事实。

- 普通鼓励、进度、统计和固定答案判题禁止调用大模型。

- AI 额度用尽、网络异常或服务不可用时，用户仍能完成今日复习。

AI 规划边界 MVP 中的“AI 规划者”是对固定课程骨架进行受限推荐，不是从空白开始生成整天课程。这个收缩保留了个性化价值，也使结果可解释、可测试、可回退。

# 8. MVP 数据范围

本节只冻结“必须保存什么”，不定义详细表结构、字段类型或服务端方案。默认本地优先。

| 数据组         | 第一版必须保存                                                                            | 用途 / 边界                                 |
| -------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------- |
| 学习者设置     | 当前语言、每日时长、学习重点、声音/语速、主题、减少动态、首次设置状态。                   | 不等同于账号；不含跨设备身份。              |
| 内容资产       | 内置词条引用、用户词、用户覆盖、收藏、文件夹、基础五十音与 IPA 内容版本。                 | 沿用既有迁移规格；避免复制全部内置内容。    |
| LearningEvent  | 答对/答错、忘记/模糊/认识、实际输入、错误选项、提示、耗时、重听、跳过、修改等有价值事件。 | 行为事实只追加或版本化修正；不被 AI 覆盖。  |
| 简版能力画像   | 近期错项、易混淆组、平均答题速度、提示依赖、重听倾向、近期趋势、基础技能状态。            | 由事件聚合，可重建；只发送摘要给 AI。       |
| 掌握与 FSRS    | 词条/技能的当前学习状态、FSRS 卡片状态、到期时间和必要复习日志。                          | FSRS 只负责复习时点；不代替行为记录与画像。 |
| 会话与今日计划 | 计划日期、区块、预计时长、完成进度、暂停位置、会话结果。                                  | 支持继续学习与解释下一次调整。              |
| 题目内容       | 通过 Schema 的题目、答案、解释、题型、来源、生成版本、验证状态与缓存信息。                | 未通过验证的 AI 内容不得作为正式题目。      |
| 迁移与安全     | 迁移版本、迁移报告、冲突与跳过项、备份元数据、回收站必要记录。                            | 确保可审计、可恢复；按既有迁移规格执行。    |

## 不作为 MVP 数据的内容

- 云端账号、订阅权益、支付记录和跨设备冲突状态。

- 用户录音、发音评分轨迹与实时语音对话流。

- 完整 AI 推理过程或未经验证的模型画像标签。

- 为“错题本”重复存储一套事实；错题视图应从 LearningEvent 与状态派生。

- 为了未来可能需要而预先建立的复杂语法图谱、课程树或社交关系。

# 9. 技术风险分析

| 风险          | 个人开发者最可能遇到的问题                       | 降低风险方案                                                                      | 预警信号                                         |
| ------------- | ------------------------------------------------ | --------------------------------------------------------------------------------- | ------------------------------------------------ |
| AI 成本与波动 | 生成频率失控、重复调用、模型输出不稳定。         | 小批量生成、缓存、每日限额、按需解释、模板回退；记录每类调用成本。                | 一次学习会话触发多次相同请求；AI 失败阻断答题。  |
| 数据结构漂移  | 题目、事件、画像与迁移各自演化，后期无法解释。   | 先冻结最小 Question / LearningEvent 合同并版本化；画像必须可由事件重建。          | 新增题型必须修改多处；同一行为有多个含义。       |
| UI 复杂度     | 每个题型各写页面，移动端、深色与无障碍测试爆炸。 | 只保留选择、输入两类原语和音频模块；/ui-lab 验证状态；统一反馈层。                | 出现第三套相似答题状态或多份进度逻辑。           |
| 语音兼容      | 浏览器 TTS 音色、语速和可用性不同。              | MVP 只承诺播放与重听；检测能力、允许关闭声音、准备无音频替代。                    | 音频失败让题目无法作答。                         |
| v1 迁移       | 历史数据边界复杂，错误迁移会失去用户信任。       | 按既有规格做只读快照、预演、报告、冲突隔离和可恢复备份；迁移不与 UI 重构混写。    | 迁移后数量不守恒、FSRS 到期异常、用户覆盖丢失。  |
| 性能与离线    | 大词库、事件增长和 AI 缓存拖慢 PWA。             | 按需加载词库、索引常用查询、聚合近期画像、缓存设上限、离线只保证基础闭环。        | 首页生成计划明显卡顿；事件越多越慢。             |
| 测试负担      | 双语言、迁移、音频和 AI 组合使回归难以覆盖。     | 先做一条日语垂直切片，再复用到英语；使用固定样例集与验收清单；AI 输出做契约测试。 | 修复一种语言破坏另一种；线上才发现 Schema 分支。 |
| 范围失控      | “顺手加入”高级题型、账号或语音导致首版无法结束。 | 以本文件为变更门槛：新增项必须替换同等工作量，而非叠加；Phase 3 不阻塞 MVP。      | 未完成核心闭环前已出现社区、支付或 ASR 工作。    |

# 11. MVP 完成与变更控制

## MVP 完成定义

- 日语与英语均可通过同一引擎完成“今日计划—作答—记录—下次调整”，但课程深度可以不同。

- v1 核心资产按既有迁移规格完成迁移核对，并提供迁移报告与恢复路径。

- 所有 AI 题目先过 Schema 与内容校验，再进入固定 UI；任何 AI 故障均有规则或内置内容回退。

- LearningEvent 能解释画像摘要，画像摘要能解释下一次课程中的至少一个变化。

- 手机端、深色模式、安全区域、减少动态和基础 WCAG 可读性通过验收。

- ASR、实时语音、账号同步、商业化、社区和自建模型均未被偷偷加入 MVP 依赖。

## 范围变更规则

唯一准入原则 新增功能只有在“直接修复核心闭环无法验证的问题”时才能进入 MVP；否则进入延期清单。若必须加入，需同时移出一项同等或更高工作量的功能。

| 变更提议            | 默认决定       | 可改为 MVP 的证据                                  |
| ------------------- | -------------- | -------------------------------------------------- |
| 增加新题型          | 延后           | 现有选择/输入原语无法验证关键学习行为。            |
| 增加独立页面        | 延后或改抽屉   | 现有六个容器无法完成主任务且会造成信息混乱。       |
| 每题调用 AI         | 拒绝           | 无；与成本、离线和稳定性边界冲突。                 |
| 加入 ASR / 实时语音 | Phase 3 或未来 | Phase 2 已验证价值，且语音本身有独立、可测的需求。 |
| 加入账号同步        | Phase 3        | 本地数据合同稳定，且试用者明确受多设备阻碍。       |
| 自建模型            | 未来独立立项   | 第三方 API 成本或能力已成为经数据证明的主要瓶颈。  |

## 最终冻结结论

第一版的产品形态 一个本地优先、可迁移、以“今日学习”为唯一主路径的双语学习 PWA。它用两类固定题目 UI、TTS、LearningEvent、简版画像和 FSRS 形成稳定闭环，再用受约束的 AI 增强计划相关性、题目语境和错误解释。除此之外的能力均不阻塞 MVP。

本文件经确认后，作为 Phase 0—2 的范围基线。完整产品愿景继续保留在 v2 产品方向决策表中，但不自动转化为 MVP 工作项。
