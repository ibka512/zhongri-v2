# 阅读结论

- 核心定位：AI 外教是调度者与反馈者，不是把所有功能塞进聊天框。

- 核心数据：LearningEvent 是行为事实；用户画像是聚合判断；FSRS 只负责长期到期调度。

- 核心交互：首页展示今日计划、预计时间、待复习、薄弱点与继续学习；专项训练降为二级入口。

- 核心差异化：保留中文母语者“看汉字先判断是否已知”的筛选逻辑，但重做为可验证诊断。

- 核心红线：AI 只生成符合固定 Schema 的题目数据，前端使用预先写好的题型组件；AI 不生成布局。

- 核心迁移原则：保留可持久化事实，不根据不存在的数据补写历史；FSRS 卡原值迁移，不重算。

# 1. v2 产品定位

一句话定位 钟日 v2 是面向中文母语者、当前聚焦日语与英语的 AI 个性化语言学习伙伴：它持续记录学习行为、识别薄弱点、生成结构化练习、安排每日课程，并用长期复习维持记忆。

产品从“工具箱”转向“学习闭环”。用户仍可主动进入词库、专项训练和自由询问，但默认路径由系统解释今天学什么、为什么安排、需要多久，以及完成后发生了什么变化。

# 2. v2 核心用户价值

每天不再做选择题 打开即知道今天学什么、预计多久、先复习还是先补弱。

练习真正针对自己 系统依据真实错误、混淆、速度、提示依赖与遗忘风险安排内容。

AI 反馈可执行 AI 解释错误、生成例句和批改开放题，但所有题目进入固定答题组件。

基础能力有课程 五十音和 IPA 不是静态表，而是可诊断、可练习、可复习的渐进课程。

长期记忆不断线 迁移 v1 FSRS 卡与历史，以相同记忆连续性进入新每日计划。

个人内容不丢失 用户词、覆盖、收藏、文件夹、错题、AI 历史、备份和回收站均有明确去向。

# 3. v2 核心学习闭环

| 环节 | 用户看到的结果 | 系统职责                                                |
| ---- | -------------- | ------------------------------------------------------- |
| 1    | 理解目标       | 语言、等级、时间预算、诊断结果与迁移先验                |
| 2    | 生成今日计划   | 规则先排 FSRS 到期与基础课程；AI 补充个性化题目         |
| 3    | 结构化练习     | Schema 校验 → questionType → 固定组件 → 程序／AI 判题   |
| 4    | 记录事实       | 每次有价值操作写 LearningEvent；不只保存最终掌握        |
| 5    | 更新画像       | 聚合薄弱点、混淆组、稳定度、速度和提示依赖              |
| 6    | 安排复现       | FSRS 决定长期复习时点；课程系统决定练什么、以何种题型练 |
| 7    | 解释与激励     | 规则生成常规气泡；AI 处理个性化解释、例句与开放反馈     |

职责分工 LearningEvent = 事实；用户画像 = 对事实的可更新总结；FSRS = 长期到期时间；AI 外教 = 在规则与成本约束下编排、生成和解释。四者不能互相伪造历史。

# 4. 决策分类说明

| 处理方式                               | 在本文中的含义                                              |
| -------------------------------------- | ----------------------------------------------------------- |
| 1. 原样保留                            | 保留用户价值、数据语义与核心行为；不等于复制 v1 代码。      |
| 2. 保留数据，但重做交互                | 历史与偏好迁移，新版入口、反馈和流程重新设计。              |
| 3. 降级为 AI／课程系统可调用的训练工具 | 不再作为首页模式，由课程策略按需组合调用。                  |
| 4. 合并进新版系统                      | 能力或数据进入今日课程、画像、题目引擎、AI 外教或安全中心。 |
| 5. 删除                                | 从 v2 用户产品中移除；必要时仅存档历史或保留内部运营工具。  |

说明：“数据是否迁移”遵循已完成的数据迁移规格。标为“删除”的旧行为，如果仍存在历史数据，可能继续迁移到只读档案或新版派生视图；删除行为不等于删除用户数据。

# 7. MVP 功能列表

MVP 边界 完整 MVP 的目标不是“功能最多”，而是让一个用户从迁移／诊断进入今日计划，完成结构化题目，产生 LearningEvent，更新画像，并被 FSRS 正确安排下一次复习。

- v1 原位迁移、备份恢复、稳定 ID 校验与可回滚报告。

- 日语／英语双语言内容中心：内置词、用户词、覆盖、收藏、文件夹与搜索。

- 今日计划首页、继续学习、预计时间、待复习、薄弱点专项。

- LearningEvent 与基础画像聚合；旧布尔掌握只作为先验，不反造事件。

- FSRS 到期调度整合到今日课程；迁移卡片原值不重算。

- 重做后的筛选诊断，保留中文母语者“见汉字先判断”的特色。

- 结构化题目 Schema、校验器、固定答题壳及核心题型组件。

- 基础 AI 外教：错误解释、语法提示、个性化例句、开放造句反馈；自由询问为次级入口。

- 规则型 AI 气泡：进度、鼓励、提示按钮；限制主动出现频率。

- 五十音与 IPA 基础路径；TTS、听力选择、听写、重播和语速。

- 错题／薄弱点派生视图、学习趋势与自动学习日。

- PWA 离线核心、深色模式、WCAG、手机安全区域、减少动态、数据安全中心。

# 8. 第二阶段功能列表

- 完善多选、句子排序、配对等复杂题型的可访问交互与编辑器。

- 更强的语法、翻译、开放回答判定；建立 AI 评分置信度与人工纠错回路。

- ASR 跟读、朗读、发音反馈、语音回答；日语音调和英语最小对立音深化。

- 三轮通关重构为自适应混合测验；AI 收词与词条补全并入统一内容流程。

- 周学习总结、提示依赖、混淆网络和更细的难度调节。

- Web／更多平台提醒、通知频率治理与订阅能力开关（不定义价格）。

- 若有服务端条件，再评估账号、跨设备同步与安全的 AI 代理；不作为当前既定前提。

# 9. 远期功能列表

- AI 实时语音外教、情景对话、根据回答继续追问与口语任务。

- 连读、弱读、语调、长句朗读与更细的发音诊断。

- 自建小模型服务、本地／服务器端 TTS、ASR 与成本优化。

- 高级个性化课程、深度语音训练和付费 AI 外教能力；价格另行验证。

- 为其他语言预留内容／技能／题型扩展边界，但本轮不设计具体课程。

# 10. 明确删除的旧行为

- 删除首页五个学习模式并列作为主入口；改为今日计划与继续学习。

- 删除普通模式“整组完成后自动把三个维度全部标为掌握”。

- 删除筛选检验“两维为真自动补齐第三维”。

- 删除把 needsReview、错题、三维掌握、FSRS 当作四套并行真值的做法。

- 删除只保存最终掌握结果、忽略关键作答过程的记录方式。

- 删除 AI 在聊天文本中自由出题并直接展示的路径；题目必须通过 Schema 与固定组件。

- 删除 AI 自由生成前端布局或交互控件的可能性。

- 删除聊天框作为学习首页和主要课程入口；保留自由询问二级入口。

- 删除每题都调用模型生成鼓励气泡；普通鼓励、剩余题数和统计使用规则模板。

- 删除 DeepSeek 直连作为产品核心架构；保留提供商适配与私测 BYOK 可能。

- 删除长按 1.5 秒手工打卡；以有效 LearningEvent 自动计算学习日。

- 删除固定 10／7 分组作为所有学习的默认节奏；仅保留为可调用批次策略。

- 删除“夜间按钮质感”等实现级设置以及与旧页面绑定的最近布局偏好。

- 删除历史 word.srs 的活跃化、运行中队列迁移、SW Cache 迁移和 OS 排程实例迁移。

迁移例外 删除旧行为时不得回写或纠正用户历史。v1 已经形成的三维掌握、组完成、错题和 FSRS 事实仍按迁移规格保留，只是 v2 不再沿用产生这些结果的错误规则。

# 13. 主要产品风险

| ID  | 风险                     | 影响                                                                       | 建议控制                                                                               |
| --- | ------------------------ | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| R1  | MVP 范围过大             | 同时包含迁移、题型引擎、画像、AI、五十音、IPA、TTS 和新 UI，交付风险最高。 | 以纵向闭环为切片：一门语言也必须跑通“计划—答题—事件—画像—复习”；题型按组件成熟度启用。 |
| R2  | AI 题目与解释不可靠      | 错误答案、差干扰项和不自然例句会伤害学习效果。                             | Schema、规则校验、内容白名单、置信度、抽样评审、用户纠错和回退模板。                   |
| R3  | 开放题误判               | AI 评分可能把可接受答案判错。                                              | 固定答案优先程序判；开放题返回维度化反馈和不确定性，不强行二元定论。                   |
| R4  | 事件量与隐私             | LearningEvent 高频、细粒度，未来同步会形成敏感学习画像。                   | 最小化采集、分层保留、聚合摘要、导出／删除、明确同意；模型只接收必要摘要。             |
| R5  | FSRS 与能力模型互相覆盖  | 两个系统都修改“掌握”会造成循环矛盾。                                       | 职责固定：FSRS 只排到期；能力模型解释表现；课程调度综合二者但不反写历史。              |
| R6  | 迁移关系断裂             | 稳定 ID、英语维度、override 和 FSRS 任何误迁都会损坏连续性。               | 执行迁移规格 V01–V25；P0 零容忍，原值不重算，原子提交和回滚。                          |
| R7  | 第三方 API 成本／可用性  | 模型、TTS、ASR 可能涨价、限流或区域不可用。                                | 提供商适配、配额、缓存、规则优先、离线降级和成本仪表。                                 |
| R8  | 日语／英语差异被过度统一 | 统一题型可能忽略假名、汉字、音标、拼写和听力的不同机制。                   | 共享题目壳与事件合同，语言课程和技能映射独立。                                         |
| R9  | 提醒造成打扰             | 根据画像的智能提醒如果过频会被关闭权限。                                   | 默认克制、静默时段、频率上限、可解释原因、一次性延后和效果监测。                       |
| R10 | AI 气泡干扰答题          | 主动提示可能泄题、打断心流或增加视觉负担。                                 | 只在停顿、连续错误或里程碑触发；可关闭；不遮挡题目和答案控件。                         |
| R11 | 离线体验断裂             | AI 和在线 TTS 不可用时用户可能无法继续。                                   | 每日计划预生成、固定题离线判分、本地 FSRS、缓存音频和清晰的能力降级。                  |
| R12 | 无障碍与玻璃风格冲突     | 低对比、动态和透明层可能不满足 WCAG。                                      | 实色内容层、对比度门槛、减少动态、安全区域和真机读屏测试。                             |
| R13 | 商业化前内容授权不足     | 词库、例句或 AI 派生内容可能存在再分发风险。                               | 建立来源链、许可审计、生成内容标记和下架机制。                                         |

# 14. 视觉与交互执行边界

- 内容像纸：题目、解析、长文本与学习记录使用高可读性的实色内容层。

- 控件像玻璃：Liquid Glass 仅用于浮动导航、底栏、AI 气泡、音频控制器和弹窗。

- AI 像柔光：表达存在感但不遮挡题目、不抢答、不频繁闪动。

- 日间使用和纸白、浅青、琉璃蓝、鸢尾紫；暗色使用深灰蓝和墨色，不使用纯黑。

- 游戏感只表达进度、连续表现和掌握变化，不堆金币、宝箱或幼稚卡通。

- 先以真实 CSS／网页组件在 /ui-lab 验证题型、动效、深色与无障碍，再决定是否补 Figma。

- WCAG 对比度、读屏语义、键盘操作、手机安全区域和减少动态是发布门槛。
