# 1. 产品定位

一句话定义 钟日 PWA 是一款中文界面的日语／英语本地优先词汇学习应用，通过词书、五种学习模式、FSRS 到期复习、错题本和 AI 辅助，把“选词—学习—判断掌握—复习—查看进度”集中在同一个 App 中。

## 1.1 当前 App 是什么

- 形态：无前端框架的单页 PWA，同时通过 Capacitor 提供 Android 包装版本。

- 语言范围：日语与英语。日语内置 JLPT N5–N1 词库；英语内置 CET-4／CET-6 词库。

- 核心对象：单词、词书／文件夹、三维掌握状态、学习记录、错题记录、FSRS 复习卡、AI 对话与测验记录。

- 数据策略：用户数据默认保存在设备本地；核心学习功能可离线使用。AI 对话需要联网并由用户配置 DeepSeek API Key。

- 用户身份：当前代码未实现账号体系，也未实现服务器端同步。

## 1.2 当前解决的问题

- 把内置词库和用户自建词汇统一为可搜索、可分组、可编辑的学习材料。

- 将词汇掌握拆为三个可记录维度：日语为汉字／读音／释义，英语为拼写／听力／释义。

- 通过浏览、选择、拼写、听辨和循环重排等交互，支持不同强度的记忆训练。

- 通过错题本和 FSRS 到期卡，把错误与长期复习从一次性练习中保留下来。

- 通过 AI 对话、例句解析、词汇提取和测验，把开放式语言问题转为可继续学习的数据。

- 通过本地备份、恢复点和回收站，降低本地数据误操作带来的损失。

## 1.3 产品边界

| 边界项   | v1 当前范围                                                       |
| -------- | ----------------------------------------------------------------- |
| 学习内容 | 日语、英语词汇；支持内置词条与用户导入词条。                      |
| 学习结果 | 三维布尔掌握状态、需复习标记、学习记录、错题记录、FSRS 卡及日志。 |
| AI 能力  | DeepSeek 流式对话、例句分析、词汇提取、词条补全、结构化测验。     |
| 离线能力 | 词库浏览、普通学习、进度与本地数据操作；AI 不在离线范围内。       |
| 多端能力 | PWA 与 Android 包装；代码中没有账号和跨设备同步。                 |
| 文档边界 | 只复述 v1 当前能力，不把架构缺口解释为未来功能需求。              |

# 2. 用户完整流程

主流程说明 以下使用“首次打开后进行一次筛选检验”为主线，因为该模式完整覆盖选词、作答、掌握判断、错题记录与 FSRS 安排。其他模式的分支在主流程后单独说明。

## 2.1 第一次打开 App：初始化

用户行为：用户打开 PWA 或 Android App。

系统处理与反馈：系统读取本地语言、词库、词条覆盖、文件夹、收藏、学习记录、掌握状态、FSRS、错题本、AI 记录和设置。若设备没有历史数据，当前代码以日语作为默认语言并加载对应内置词库；英语词库在切换时按需加载。

数据影响：初始化或迁移后的本地数据；首次打开时可能写入默认设置与数据版本信息。

## 2.2 进入首页：理解当前状态

用户行为：用户查看今日 FSRS 到期数量、连续打卡、总体掌握和三个维度的掌握条，并确认当前学习范围。

系统处理与反馈：首页根据当前语言筛选词条，计算词库总量、掌握统计、到期复习量和学习范围文案。底部导航提供首页、全景词库、AI 对话和设置入口。

数据影响：此步以读取为主；仅在界面状态和必要迁移时写入数据。

## 2.3 选择学习语言与范围

用户行为：如需切换语言，用户进入设置首页选择日语或英语词书；返回首页后打开“学习／复习范围”，选择文件夹、虚拟筛选范围或词组。

系统处理与反馈：切换语言后，首页、词库和 FSRS 到期列表同步按该语言刷新。普通模式使用每组 10 词、步长 7 的重叠分组；筛选检验拥有独立的范围与检验内容选择。

数据影响：当前语言、已选范围、学习模式相关偏好。

## 2.4 选择功能：进入筛选检验

用户行为：用户选择检验范围和内容：单词／假名或拼写／听力／释义，然后点击“筛选检验”。

系统处理与反馈：系统根据当前语言、范围、排序设置和“跳过已掌握”设置生成题目队列，并进入全屏学习区。

数据影响：主要写入临时学习会话状态；尚未形成最终作答结果。

## 2.5 查看题面并自评

用户行为：用户根据题面选择“忘记”“模糊”或“认识”。

系统处理与反馈：“忘记”直接形成错误；“模糊”只展示一个随机辅助提示，不立即判定；“认识”展示完整答案，随后要求用户确认正确或错误。

数据影响：“模糊”本身不写入掌握或 FSRS；“忘记”或后续确认才产生最终结果。

## 2.6 系统处理单题结果

用户行为：用户确认正确或错误后进入下一题。

系统处理与反馈：正确会把当前检验维度标为掌握；错误会把该维度标为未掌握并设置“需要复习”。若同一词已有任意两个维度为真，当前代码会自动补齐第三维。三个维度都为真时清除“需要复习”。

数据影响：单词掌握状态、需要复习标记、错题本统计、FSRS 卡与复习日志。筛选检验中的正确映射为 FSRS Good，错误映射为 Again。

## 2.7 完成本次任务

用户行为：用户完成队列中的全部词，或使用完成／退出操作结束当前学习。

系统处理与反馈：系统显示完成反馈并保存本次变更。普通学习模式当前没有统一的独立结果页；学习结果主要通过提示、首页掌握条、记录、错题本和 FSRS 到期状态体现。

数据影响：学习记录或模式完成记录、掌握状态、错题和复习数据；具体写入随模式不同。

## 2.8 查看结果

用户行为：用户回到首页查看总体和分维度掌握变化；也可进入全景词库查看单词颜色／状态、进入错题本看错误记录，或在到期后从首页开始 FSRS 复习。

系统处理与反馈：首页和词库从本地数据重新计算并展示最新状态。AI 测验是当前少数具有独立结果视图的流程，会展示题目级正确性并保存测验历史。

数据影响：查看本身通常不新增业务数据；若继续复习或纠错，会追加相应记录。

## 2.9 其他学习入口的流程差异

| 入口          | 用户流程                                                            | 完成后的当前结果                                                           |
| ------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 自由浏览      | 选择范围 → 前后浏览交错词卡 → 切换完整／单一内容显示 → 完成         | 完成时把本组唯一词条的三个维度全部标为掌握，并增加组完成记录。             |
| 往复检验      | 选择范围 → 释义选择与拼写任务循环出现 → 错误留在当前任务 → 完成     | 正确才推进；完成时把本组词条三个维度全部标为掌握；错误进入错题本。         |
| 循环强记      | 选择训练维度 → 首次完整预览 → 两步训练 → 错误重排 → 完成            | 每个词按语言和维度执行固定两步；完成时把本组词条三个维度全部标为掌握。     |
| 三轮通关      | 选择范围 → 三轮不同题型 → 错题移到轮末重做 → 三轮全部完成           | 三轮完成后把本组词条三个维度全部标为掌握。                                 |
| FSRS 到期复习 | 首页点击开始复习 → 查看到期卡 → 选择 Again／Hard／Good／Easy → 完成 | FSRS 根据评分计算下次到期时间；更新卡片状态和复习日志。                    |
| AI 测验       | AI 对话中生成测验 → 作答 → 查看题级反馈和结果                       | 保存测验历史；可将匹配词条的错误写入错题本，并把未收录词送入 AI 收词流程。 |

# 3. 功能模块

模块划分 模块按用户可感知能力划分。由于 v1 是单页应用，以下“模块”不代表独立技术包，也不代表独立路由。

## 3.1 首页

功能目的：汇总当前语言下的学习状态，并提供所有主要学习入口。

用户操作：查看今日 FSRS、连续打卡、总体与三维掌握；选择学习范围；进入筛选检验、自由浏览、往复检验、循环强记、三轮通关；长按 1.5 秒打卡；使用底部导航。

系统反馈：实时显示到期维度数量、掌握比例、当前范围和模式入口；完成打卡后提供触觉／声音与提示反馈。

保存的数据：当前语言、范围和模式偏好；长按打卡成功后新增一条 daily_punch 学习记录。

## 3.2 学习模式

功能目的：用不同强度和题型完成词汇识别、回忆、拼写、听辨与循环巩固。

用户操作：选择范围与训练内容，按模式浏览、选择、拼写、听音或自评，直到完成队列。

系统反馈：显示进度、题面、提示、正确／错误反馈和完成提示；失败项会按模式留在原位或重新排入队列。

保存的数据：掌握状态、需要复习标记、学习／组完成记录、错题记录；筛选检验另写入 FSRS。

| 模式     | 核心交互                | 可选内容                     | 当前结果语义                   |
| -------- | ----------------------- | ---------------------------- | ------------------------------ |
| 筛选检验 | 自评 + 最终确认         | 当前检验维度                 | 正确／错误逐题更新；写入 FSRS  |
| 自由浏览 | 交错词卡浏览            | 完整、单词、读音／听力、释义 | 完成后整组全掌握               |
| 往复检验 | 释义选择 + 拼写循环     | 模式内置                     | 错误不推进；完成后整组全掌握   |
| 循环强记 | 首次预览 + 固定两步训练 | 单词／读音或听力／释义       | 错误重排；完成后整组全掌握     |
| 三轮通关 | 三轮选择、听辨与拼写    | 模式内置                     | 错题移到轮末；三轮后整组全掌握 |

## 3.3 FSRS 复习系统

功能目的：把筛选检验产生的词条维度转为有到期时间的长期复习卡。

用户操作：从首页查看到期数量并开始复习；对每张卡选择 Again、Hard、Good 或 Easy。

系统反馈：显示当前维度、进度和各评分对应的下一次间隔预览；完成后首页到期数量刷新。

保存的数据：按“语言 + 单词 ID + 维度”保存 FSRS 卡；保存评分、时间和调度结果日志，日志最多保留 500 条。

## 3.4 错题本

功能目的：聚合普通学习、筛选检验和 AI 测验中的错误，支持按错误维度再次练习。

用户操作：按拼写、听力、读音、释义、用法、语法、AI、反复错误或已解决筛选；查看单词错误摘要；开始错题练习；关闭／开启新错题记录。

系统反馈：显示总错误、总正确、最近答案、连续正确、重复错误和已解决状态；错题练习取当前筛选前 20 个词，每词出现两次。

保存的数据：每个词的分维度统计、来源、最近答案（最多 20 条）、correctStreak、resolved／repeated 状态和全局记录开关。

## 3.5 词书／全景词库

功能目的：浏览、搜索、筛选、整理和维护当前语言的全部词条。

用户操作：搜索单词／假名或释义；按文件夹、收藏、掌握状态、错题、等级和难度筛选；切换 2／3／4 列与内容显示；收藏；进入管理模式批量移动、编辑或删除；创建／删除自定义文件夹。

系统反馈：虚拟化网格呈现词卡与掌握状态；筛选和布局改变后即时刷新；删除内容进入回收站。

保存的数据：搜索与视图偏好、收藏、文件夹与语言映射、用户词条、内置词条覆盖／删除标记、回收站项目。

## 3.6 单词详情

功能目的：集中查看单词的完整资料、掌握与错误信息，并进入语音、收藏、编辑和 AI 上下文能力。

用户操作：前后切换词条；播放 TTS；收藏；查看词性、释义、例句、等级、难度、词根等；编辑用户数据；打开上下文 AI 解析。

系统反馈：按语言呈现汉字／假名或英文／音标；显示例句、掌握条和错题摘要；AI 返回骨架拆解、核心亮点和举一反三内容。

保存的数据：收藏状态、编辑后的用户词条或内置覆盖、AI 对话／缓存、保存到词条的例句。

## 3.7 AI 功能

功能目的：用开放式对话和结构化处理辅助理解语言材料，并把 AI 结果回收到词库或测验。

用户操作：配置 API Key；选择自由、语法、词汇、润色或引导预设；进行流式对话；分析例句；保存例句；从回答提取最多 12 个词；生成结构化测验；查看／删除对话。

系统反馈：流式显示 DeepSeek 回答与推理过程；对提取词进行批量补全、预览和编辑；测验按题反馈并提供结果。

保存的数据：本地 API Key、AI 会话、系统提示词与预设、例句分析缓存、收词草稿与保存结果、AI 测验历史。API Key 不进入备份。

## 3.8 设置

功能目的：集中管理语言、学习行为、显示与语音、AI、词库数据和 App 级操作。

用户操作：切换日语／英语；设置排序与跳过已掌握；切换错题／测验记录；设置词根、自动朗读、注音显示、纹理、TTS、触觉；管理 AI Key；导入／审计词库；管理提醒、备份、恢复与重置。

系统反馈：设置保存后立即影响首页、学习、词库、声音、触觉、AI 或通知调度；高风险数据操作通过确认、恢复点或回收站提供反馈。

保存的数据：各类偏好、提醒计划、备份数据、迁移版本、恢复点、回收站与重置后的保留项。

## 3.9 数据导入、备份与恢复

功能目的：让用户在本地扩展词库，并迁移或恢复完整学习数据。

用户操作：手工导入 CSV／TSV；AI 导入最多 100 个词并分批处理；处理重复词；导出 JSON 备份；导入备份；撤销导入；重置进度、恢复内置词库或全部重置。

系统反馈：导入前预览与校验；重复项支持跳过、覆盖或保留；导入备份前创建安全恢复点；删除内容进入 7 天回收站。

保存的数据：用户词条、内置覆盖、文件夹、收藏、记录、掌握、AI、FSRS、错题、测验、回收站、偏好和恢复点。DeepSeek API Key 明确排除在备份之外。

## 3.10 PWA 与 Android 原生能力

功能目的：提供可安装、离线缓存、触觉反馈和 Android 学习提醒。

用户操作：安装／打开 PWA；在支持设备上使用 TTS 与触觉；Android 用户配置固定或智能提醒、到期提醒、补救提醒、星期、静默时段和测试通知。

系统反馈：Web 端由 Service Worker 提供缓存；Android 包装版本使用原生资源并关闭 Web Service Worker；通知可直接开始复习或延后 30 分钟。

保存的数据：PWA 缓存不属于业务数据；保存 Android 提醒设置与重排状态。Web 通知当前不提供。

# 4. 学习系统逻辑

## 4.1 单词如何进入学习

- 系统先按当前语言选择日语或英语词条；当前语言同时约束首页统计、词库、学习队列和 FSRS 到期卡。

- 用户从文件夹、内置等级、收藏、错题、已掌握／未掌握维度等范围中选择学习对象。

- 普通学习模式按“每组 10 词、步长 7”形成重叠分组；相邻组共享部分词条。

- 筛选检验使用独立的范围与检验内容设置，并可按薄弱优先、新词优先或原始顺序排序，也可跳过已掌握内容。

- 进入模式后生成临时队列。模式决定每个词出现几次、题型顺序以及错误后是停留还是重新排队。

## 4.2 三维掌握模型

| 语言 | 维度一 | 维度二       | 维度三 |
| ---- | ------ | ------------ | ------ |
| 日语 | 汉字   | 读音（假名） | 释义   |
| 英语 | 拼写   | 听力         | 释义   |

- 每个维度以“已掌握／未掌握”布尔值保存；另有 needsReview 标记表示词条需要复习。

- 英语沿用历史字段名保存三维结果：代码中的 kanji 实际表示拼写，kana 实际表示听力。

- 筛选检验中，任意两个维度为已掌握时，代码会自动补齐第三个维度；三个维度均为真时清除 needsReview。

- 自由浏览、往复检验、循环强记和三轮通关在整组完成时，直接把该组唯一词条的三个维度全部标为已掌握。

## 4.3 “忘记／模糊／认识”的含义

| 选择 | 用户语义                           | 系统即时行为                           | 最终数据影响                                                                 |
| ---- | ---------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------- |
| 忘记 | 用户无法回忆当前检验内容。         | 立即按错误处理并进入下一处理步骤。     | 当前维度设为未掌握；needsReview 设为真；错题本记录错误；FSRS 以 Again 评分。 |
| 模糊 | 用户不确定，需要额外提示后再判断。 | 随机展示一个辅助信息，停留在当前词。   | 此按钮本身不判对错，也不更新掌握、错题本或 FSRS；最终仍需确认。              |
| 认识 | 用户认为自己能回忆当前内容。       | 展示完整答案，要求再次确认正确或错误。 | 只有最终确认才写入掌握、错题和 FSRS；确认正确对应 Good，确认错误对应 Again。 |

不确定 “模糊”没有独立持久化等级，因此无法从现有数据还原用户历史上的“模糊次数”。其产品含义在 v1 中是一个中间交互状态，而不是第三种最终掌握结果。

## 4.4 单题结果如何影响数据

| 事件             | 掌握状态                                                           | 长期复习                               | 其他记录                                   |
| ---------------- | ------------------------------------------------------------------ | -------------------------------------- | ------------------------------------------ |
| 筛选检验正确     | 当前维度设为真；满足“两维为真”时补齐第三维；全真时清除 needsReview | FSRS Good                              | 错题本记正确，用于连续正确与解决状态       |
| 筛选检验错误     | 当前维度设为假；needsReview 设为真                                 | FSRS Again                             | 错题本记错误并累计维度与来源               |
| 普通模式过程错误 | 按模式停留或重排；不一定立即改变三维掌握                           | 不新建 FSRS 卡                         | 支持的题型写入错题本                       |
| 普通模式整组完成 | 组内唯一词条三个维度全部设为真                                     | 不因完成而新建 FSRS 卡                 | 保存组完成／学习记录；具体模式可同时有错题 |
| FSRS 到期评分    | 不直接等同于三维布尔值切换                                         | Again／Hard／Good／Easy 驱动下一次调度 | 追加 FSRS 日志                             |

## 4.5 五种学习模式的队列与通关逻辑

| 模式     | 队列                                          | 错误处理                                   | 完成条件         |
| -------- | --------------------------------------------- | ------------------------------------------ | ---------------- |
| 筛选检验 | 按范围与内容生成逐词队列                      | 忘记直接错；模糊给提示；认识后确认         | 队列处理完       |
| 自由浏览 | 将所选词交错排列，可前后移动                  | 无逐题判分；可切换显示内容                 | 用户完成浏览     |
| 往复检验 | 每词按 5 次循环：前 3 次释义选择、后 2 次拼写 | 选择错误或拼写错误不推进；失败后可出现提示 | 所有词完成循环   |
| 循环强记 | 首现完整预览；之后按语言和维度执行两步        | 失败项重新入队                             | 每词固定两步通过 |
| 三轮通关 | 基础队列打乱；每轮失败项移到末尾              | 每轮题型不同，直到本轮无失败               | 三轮全部清空     |

## 4.6 循环强记的固定两步

| 训练对象  | 步骤一                          | 步骤二                          |
| --------- | ------------------------------- | ------------------------------- |
| 日语·单词 | 显示单词 → 拼写假名             | 显示单词 + 假名 → 选择释义      |
| 日语·读音 | 显示假名 → 选择单词             | 显示单词 + 假名 → 选择释义      |
| 日语·释义 | 显示释义 → 拼写假名             | 显示假名 + 释义 → 选择单词      |
| 英语·单词 | 显示释义／词性 → 拼写英文       | 显示英文／音标／词性 → 选择释义 |
| 英语·听力 | 播放语音 → 选择英文             | 显示英文／音标／词性 → 选择释义 |
| 英语·释义 | 显示英文／音标／词性 → 选择释义 | 显示释义／词性 → 选择英文       |

## 4.7 三轮通关的题型顺序

| 轮次   | 日语                                         | 英语            |
| ------ | -------------------------------------------- | --------------- |
| 第一轮 | 音频 → 选择释义                              | 音频 → 选择释义 |
| 第二轮 | 音频 → 选择单词；随后按单词拼写假名          | 音频 → 拼写英文 |
| 第三轮 | 假名 → 选择释义；随后根据假名 + 释义选择单词 | 音标 → 选择释义 |

## 4.8 复习如何安排

- 筛选检验在用户形成最终正确／错误结果时，为“语言 + 单词 ID + 当前维度”创建或更新 FSRS 卡。

- 当前调度目标保持率为 90%。具体间隔由 FSRS 根据卡片状态和 Again／Hard／Good／Easy 评分计算，不是固定天数表。

- 首页只展示当前语言下已经到期的维度卡；用户进入复习后逐张评分。

- 评分后保存卡片的新状态、下一到期时间和复习日志；首页到期数量随之更新。

- Android 可根据到期数据和固定／智能提醒设置重新安排通知；Web 端当前不提供该提醒。

当前边界 自由浏览、往复检验、循环强记和三轮通关会在完成后把词条标为全掌握，但不会因为这次完成而自动创建新的 FSRS 卡。v1 因此同时存在“即时三维掌握”和“FSRS 长期卡片”两套结果域。

## 4.9 打卡、学习日与连续天数

- 首页连续打卡统计使用 daily_punch 记录。

- Android 提醒判断“当天是否已学习”时，还会参考自由浏览完成和 FSRS 复习日志。

- 因此“首页连续打卡”和“提醒系统中的学习日”在 v1 中不是完全相同的口径。

| 数据域      | 主要内容                                                                     | 用途                                                                                               |
| ----------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |

| AI 测验历史 | id、标题、时间、耗时、总题数、正确数、逐题答案                               | 逐题记录包含题型、维度、词、提示、用户答案、正确答案、解释、是否正确和匹配词 ID；最多保留 100 次。 |
| 回收站      | id、batchId、kind、label、deletedAt、expiresAt、payload                      | 支持词条、对话和例句的撤销／恢复／永久删除；保留 7 天，最多 300 项。                               |

## 5.7 数据持久化与备份边界

- 主要业务集合通过 idb-keyval 写入 IndexedDB；在不可用时回退到 localStorage。

- 内置词库作为应用资源加载，用户词和内置覆盖分开保存，避免每次都复制完整内置库。

- 完整 JSON 备份包含词条、文件夹、收藏、学习记录、掌握、AI 会话、FSRS、错题、测验、回收站和偏好。

- 导入备份前创建安全恢复点；手工／AI 词条导入也提供导入前恢复路径。

- DeepSeek API Key 不进入备份。

- 当前数据架构没有账号标识、服务端副本或跨设备冲突合并数据。

# 7. 当前版本问题

分析边界 本节只记录代码现状对架构、维护和扩展形成的约束，不包含修改步骤、技术选型或 v2 实现方案。

## 7.1 架构问题

- 核心业务高度集中：app.js 约 1.9 万行，同时承载模型、视图、控制器、DOM 事件、学习状态、数据迁移、AI 与原生桥接逻辑。

- 全局可变状态范围过大：一个 Model.state 同时保存页面状态、模式状态、当前语言、学习队列和临时交互状态，不同功能通过字符串模式判断当前语义。

- 运行时重定义较多：多个后置 IIFE 包装或重新赋值已有方法，最终行为依赖脚本执行顺序和原方法是否已存在。

- 模块依赖依靠全局变量和脚本加载顺序建立，例如 Model、Controller、DefaultWords、FSRS 和循环强记核心之间没有显式模块边界。

- Web PWA 与 Android 行为分散在 HTML 内联初始化、app.js、native-app.js、Service Worker 和 Capacitor 配置中，平台边界不是单一入口。

- 即时三维掌握、错题统计和 FSRS 卡是三个并行状态域；相同一次学习对三者的影响因模式不同而不同。

- 内置词库以可执行 JavaScript 分块加载，内容数据、加载顺序和应用脚本发布形式相互耦合。

## 7.2 可维护性问题

- 日语／英语在渲染、标签、题型、语音和字段映射中存在大量条件分支，等价逻辑在不同流程内重复。

- DOM ID、存储键、模式名、维度名和显示文案直接散落在大文件中；改动影响范围难以通过局部阅读确认。

- 历史命名继续承载新语义：英语“拼写／听力”仍保存为 kanji／kana；自由浏览内部和记录中继续使用 pendulum。

- 数据同时涉及 IndexedDB、localStorage、内置资源、旧版完整词库、用户词、覆盖、迁移快照和恢复点，兼容路径较多。

- 备份已发展到版本 10，数据模式版本为 8；每个业务域都参与导入校验、迁移和恢复边界。

- 样式由大型 style.css、ui-system.css、HTML 内联样式和 JavaScript 动态样式共同决定，页面外观难以只从单一位置理解。

- 测试覆盖了核心算法、词库产物、持久化安全和部分契约，但大量 DOM 工作流、跨页面状态和真实设备原生行为没有同等粒度的端到端验证。

## 7.3 扩展困难点

- 语言、维度和模式由多处字符串映射与条件分支编码；新增一种语言、维度或题型会触及首页、词库、学习、错题、FSRS、AI 和备份多个区域。

- 学习模式直接操作共享状态与 DOM，模式之间可复用的“队列、题目、判分、记录、完成”边界不稳定。

- AI 功能在前端直接绑定 DeepSeek 请求地址、模型名、流式协议、提示词和结果结构；提供方、模型与 UI 工作流耦合。

- 词条字段在手工导入、AI 导入、编辑、内置覆盖、备份恢复和词库审计中重复归一化，字段扩展会扩大一致性检查范围。

- 页面切换依靠 DOM 类和全局事件，不存在声明式路由或页面状态模型；增加页面会继续扩大事件与可见性组合。

- 完整备份包含绝大多数业务域，新数据域会同时增加迁移、兼容、撤销和恢复验证面。

- 当前没有账号或服务端数据模型；现有本地数据结构未包含用户身份、设备版本或冲突合并语义。

## 7.4 当前行为与口径不一致

| 事项               | v1 当前表现                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| 英语搜索提示与实现 | 界面提示可搜索“英文、音标或释义”，当前过滤逻辑实际匹配 word、kana 和 meaning，没有匹配 phonetic。                |
| 连续打卡与学习日   | 首页连续天数只按 daily_punch 统计；Android 提醒的“已学习”还包含自由浏览完成和 FSRS 复习。                        |
| 清空学习进度边界   | 当前“清空学习进度”主要处理学习记录和三维掌握；FSRS、错题本和 AI 测验属于其他数据域，界面文字未完整表达这一区分。 |
| 普通模式完成语义   | 自由浏览及三种通关模式完成后均把组内词条三个维度设为已掌握，即使过程中没有逐词覆盖三个维度的最终自评。           |
| FSRS 来源边界      | 筛选检验会创建／更新 FSRS 卡；其他普通模式完成不会自动产生新的长期复习卡。                                       |

## 7.5 不确定项

- 不确定：“模糊”只存在于当前题目的中间状态，没有持久化记录；无法从历史数据判断其使用频率或是否应被视为独立掌握等级。

- 不确定：普通学习模式没有统一结果页。不同模式的完成反馈、退出路径和用户是否把首页统计视为“结果页”，仅靠静态代码无法确认真实使用认知。

- 不确定：内置词条中的 frequency、pitch、reviewStatus、specialTags、sourceLevels 等扩展字段并非所有词条都具备；不同来源的完整率需以词库审计报告为准。

- 不确定：Android 的精确提醒、静默时段和通知动作会受系统版本及权限影响；静态仓库只能确认调用路径，不能确认所有真实设备上的到达率。

- 不确定：PWA 缓存升级、首次安装和离线回退在不同浏览器上的实际体验，需要真实浏览器环境验证；本文只确认 Service Worker 与缓存逻辑存在。

## 8.2 需求基线结论

结论 v2 重构的需求起点不是“重新设计一款背单词 App”，而是完整承接 v1 已存在的词库、五种学习模式、三维掌握、错题、FSRS、AI、本地数据安全和 PWA／Android 交互语义。本文未增加任何新功能，也未规定未来技术实现。
