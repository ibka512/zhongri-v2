本地优先 · 事件事实 · 可重建投影 · 受约束 AI

推荐架构 React + TypeScript + Vite 构建本地优先 PWA；Dexie 管理 IndexedDB；Zustand 仅保存短生命周期界面与会话状态；学习核心使用纯 TypeScript 模块；AI 经轻量网关、版本化任务协议与双重 Schema 校验进入系统。

# 0. 使用方式与架构冻结摘要

本规范定义组件和服务之间“可以怎样协作”，不规定每个函数或表字段。实现出现冲突时，优先级依次为：数据迁移不可损失约束 → MVP 范围冻结 → Design System 组件状态 → 本技术规范中的推荐实现。

## 0.1 十项冻结决策

| 决策     | 冻结结果                                                 | 直接后果                                                        |
| -------- | -------------------------------------------------------- | --------------------------------------------------------------- |
| 应用形态 | 单页、本地优先 PWA。                                     | 核心学习不依赖登录或持续联网。                                  |
| 前端     | React + TypeScript + Vite。                              | 沿用已冻结 React 组件边界，不引入 SSR 运行时。                  |
| 数据     | 新建 v2 IndexedDB，由 Dexie 管理。                       | v1 idb-keyval 只由迁移读取器访问；LocalStorage 不作为业务主库。 |
| 状态     | Zustand 只管 App Shell 与当前会话。                      | 持久事实仍以 Repository / IndexedDB 为唯一真相。                |
| 学习核心 | 纯 TypeScript 领域模块。                                 | 不得依赖 React、CSS、浏览器 DOM 或具体数据库。                  |
| 事件     | LearningEvent 只追加；画像与 ReviewState 是投影。        | AI 推断、错题视图与进度统计不得改写事实。                       |
| 复习     | FSRS 只负责调度；算法和映射策略显式版本化。              | 迁移卡片原样作为基线，不能用 v2 事件反造 v1 历史。              |
| AI       | 任务型网关 + 结构化协议 + 双重校验。                     | 组件不能直接调模型；无效输出永不进入 Question UI。              |
| 离线     | Phase 1 的规则计划、复习、答题、事件与基础内容离线可用。 | AI 和在线同步不是基础闭环依赖。                                 |
| 原生扩展 | 平台能力统一通过 Ports；Phase 3 再接 Capacitor。         | 通知、震动、文件、生命周期调用不得散落在 feature 中。           |

## 0.2 MVP 明确不做

- 不引入账号、跨设备同步、社区、支付、订阅或商业化后台。

- 不实现 ASR、发音评分、实时语音外教、自建模型服务器或服务器集群。

- 不为句子排序、配对、开放回答等未来题型提前实现页面和交互。

- 不让 AI 直接修改 LearningEvent、LearnerProfile、ReviewState 或 StudySession。

- 不把 Redux action、数据库记录、LearningEvent 和 AI 日志混成同一种“事件”。

- 不以微服务、消息队列、云数据库或复杂 CQRS 作为 MVP 前置条件。

完成边界 Phase 1 必须在 AI、网络和音频服务失败时仍完成一次每日复习；Phase 2 只验证 AI 是否让内容更相关、解释更有帮助。只有 Phase 2 通过，才算 v2 MVP 完成。

# 1. 总体技术架构

钟日采用“领域核心 + 端口适配器”的单体前端架构。它不是微服务，也不是把所有逻辑放进 React Hook。UI 通过应用用例调用学习核心；学习核心通过端口访问存储、AI、音频和平台能力。AI 与数据层是并列适配器，不形成“数据库调用 AI”的倒置依赖。

## 1.1 分层职责

| 层                | 包含                                                                           | 职责                                       | 禁止                                              |
| ----------------- | ------------------------------------------------------------------------------ | ------------------------------------------ | ------------------------------------------------- |
| 用户界面层        | 六个页面、App Shell、Design System 组件、Question UI。                         | 呈现状态、收集意图、提供无障碍与反馈。     | 判题、生成计划、直接读写 IndexedDB、直接调用 AI。 |
| 应用 / 业务逻辑层 | Use Cases、路由协调、会话协调、事务边界、错误映射。                            | 把一次用户意图编排成领域调用和持久化动作。 | 包含 CSS、复制领域算法、绕过 Repository。         |
| 学习引擎层        | Study Engine、Question System、LearningEvent、Review Engine、Learner Profile。 | 执行可测试、可重放、与框架无关的学习规则。 | 依赖 React、DOM、具体 AI SDK 或具体数据库。       |
| 端口层            | Repository、AI、Audio、Clock、ID、Platform 等接口。                            | 描述领域需要的能力，不描述供应商。         | 泄漏 Dexie 表、HTTP Response、Capacitor 对象。    |
| 适配器层          | Dexie Repository、AI Gateway Client、Web Speech、Service Worker、Capacitor。   | 把外部能力转换成端口协议，处理平台错误。   | 决定学习规则或改写领域事实。                      |
| 外部能力          | 模型供应商、浏览器存储、canonical 内容、系统音频和 Android API。               | 提供不稳定或平台相关能力。                 | 被 UI 直接依赖。                                  |

## 1.2 允许与禁止调用

| 调用方            | 允许调用                                              | 禁止直连                                         |
| ----------------- | ----------------------------------------------------- | ------------------------------------------------ |
| React 页面 / 组件 | 应用用例、只读 ViewModel、Design System 组件。        | Dexie、fetch 模型 API、FSRS 包、迁移读取器。     |
| 应用用例          | 领域模块、Repository Ports、AI/Audio/Platform Ports。 | 具体表名、组件内部状态、第三方响应对象。         |
| 学习引擎          | 纯领域对象、策略接口、时钟/ID 等抽象。                | React、Window、Service Worker、Capacitor、网络。 |
| Repository 实现   | IndexedDB / Dexie。                                   | UI、AI、学习计划策略。                           |
| AI Service        | AI Gateway、Schema Validator、Prompt Registry。       | LearningEvent 写入、ReviewState 更新、页面路由。 |
| Service Worker    | 请求、Cache Storage、更新消息。                       | 业务表写入、FSRS 运算、AI 上下文构建。           |

## 1.3 核心学习数据流

关键事务顺序：提交意图 → 程序判题 → 原子写入 LearningEvent 与会话检查点 → 投影器按游标更新 ReviewState / LearnerProfile → UI 获得稳定 Feedback。AI 解释可以稍后到达，但不能延迟事实落地或改变判定。

事实优先 如果投影器或 AI 中断，事件仍是可恢复的事实；如果事件尚未成功写入，UI 不得显示“已记录”或推进到下一题。

# 2. 技术栈选择

## 2.1 前端框架评估

| 方案   | 优点                                                                      | 对本项目的问题                                                                | 结论                               |
| ------ | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------- |
| React  | 组件生态成熟；与已冻结 AppShell、QuestionFrame、AI Bubble 边界一致。[T01] | 需要主动约束状态和副作用位置。                                                | 推荐。保持函数组件与显式领域边界。 |
| Vue    | 模板与响应式体验友好，单人开发效率高。                                    | 当前 Design System 已按 React 组件契约冻结，切换只带来重写，不增加 MVP 价值。 | 技术可行，但不选。                 |
| Svelte | 编译期优化、组件简洁、运行时负担小。[T02]                                 | 团队与既有文档没有 Svelte 契约；未来 AI 辅助和组件生态收益不确定。            | 不作为 v2 首选。                   |

React 的选择不是因为 Vue 或 Svelte 不适合 PWA，而是因为产品设计已冻结为 React 组件边界。个人开发者最重要的是减少重新决策和跨框架翻译。

## 2.2 构建与运行方式

| 方案       | 适配度                                                               | 判断                                                                   |
| ---------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Vite       | 静态部署、快速开发、插件生态与 PWA 集成直接；不要求常驻服务端。[T03] | 推荐；使用 SPA 路由与显式 Service Worker。                             |
| Next.js    | 适合全栈、SSR、Server Components 与服务端路由。[T04]                 | MVP 不需要 SEO、SSR 或服务端页面；会扩大离线、缓存和部署心智，暂不选。 |
| 其他元框架 | 可提供约定式路由和服务端能力。                                       | 在需求出现服务端渲染或内容站之前，不增加框架层。                       |

## 2.3 语言、状态与数据

| 领域       | 推荐                                     | 边界与理由                                                                                                 |
| ---------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 语言       | TypeScript strict                        | Question、LearningEvent、AI 协议与迁移关系复杂；编译期收窄可减少结构漂移。[T05] 运行时外部输入仍必须校验。 |
| 全局状态   | Zustand                                  | 只保存主题、离线状态、当前会话 ViewModel 与短生命周期交互；API 小、样板少。[T06]                           |
| 复杂状态   | TypeScript 判别联合 + 纯 reducer         | 题目、AI、音频和迁移使用显式状态机；不额外引入 XState。                                                    |
| 业务持久化 | IndexedDB + Dexie                        | IndexedDB 适合大量结构化离线数据；Dexie 提供索引、事务与版本升级包装。[T08][T09]                           |
| 运行时校验 | Zod + JSON Schema                        | 同一协议用于 TypeScript 推断、客户端校验与 AI 结构化输出约束。[T10]                                        |
| FSRS       | ts-fsrs，经 ReviewScheduler 适配         | 锁定算法版本；v1 卡片作为迁移基线，升级必须有回放和对比测试。[T15]                                         |
| PWA        | vite-plugin-pwa + Workbox injectManifest | 保留少量自定义缓存和更新策略，不把领域逻辑放进 Service Worker。[T11][T12]                                  |

## 2.4 最终推荐栈

| 类别    | 选择                                  | 说明                                                            |
| ------- | ------------------------------------- | --------------------------------------------------------------- |
| UI      | React 19.2 系列 + React Router        | 以锁文件固定具体 patch；页面只消费 ViewModel。                  |
| 构建    | Vite 8 系列                           | 纯前端静态产物；AI Gateway 独立部署。                           |
| 语言    | TypeScript strict                     | 禁止在领域、Schema、Repository 边界使用未解释的 any。           |
| 状态    | Zustand + 局部 React state            | Zustand 不使用 persist 保存业务事实。                           |
| 数据库  | Dexie / IndexedDB                     | 新建 v2 DB；v1 idb-keyval 仅迁移读取。                          |
| 校验    | Zod / JSON Schema                     | AI、备份、迁移导入和 Question 共用版本化契约。                  |
| PWA     | vite-plugin-pwa / Workbox             | App Shell 预缓存；内容、音频和 AI 缓存分域。                    |
| 测试    | Vitest + Testing Library + Playwright | 纯领域单测、组件状态测试、离线/迁移 E2E。                       |
| AI 后端 | 薄型无状态 Gateway                    | 只做代理密钥、限额、Prompt/模型适配和服务端校验；不是业务主库。 |

## 2.5 明确不选

- 不使用 SQLite 作为 Web MVP 主库；若未来原生数据量、查询或同步要求证明 IndexedDB 不足，再替换 Repository 适配器。

- 不使用 LocalStorage 保存词条、事件、画像、题目、FSRS 或会话；仅允许主题首屏、防闪烁标记等极小启动值。

- 不使用 Redux Toolkit。它本身可靠且官方推荐用于 Redux 项目 [T07]，但当前规模下会增加样板，并容易把领域事件误当成 UI action。

- 不引入 TanStack Query 作为本地业务状态层；AI 任务数量有限，由 AI Service 自行管理超时、重试和缓存。

- 不在 Phase 0 为未来可能的云同步建立服务端 ORM、用户表或冲突合并框架。

版本策略 初始化时固定主版本与具体 patch，提交 lockfile；每季度集中升级一次。FSRS、Question Schema、LearningEvent 与迁移规格的版本升级必须独立记录，不能随依赖升级静默变化。

# 3. 前端项目目录结构

目录采用“薄 App + feature 页面 + 独立领域核心 + 基础设施适配器”。不以文件类型把所有 Hook、Service 或 Type 堆在一起；共享目录只有在至少两个功能真正复用时才创建。

| 路径                        | 职责                                                                       | 不得放入                               |
| --------------------------- | -------------------------------------------------------------------------- | -------------------------------------- |
| src/app/                    | 应用启动、Provider 组合、路由表、全局错误边界、主题与 PWA 注册。           | 学习规则、题目判定、数据库表操作。     |
| src/pages/                  | 六个页面级容器；组合 feature 与 ui 组件。                                  | 可复用领域算法和外部 API 调用。        |
| src/features/               | onboarding、today-plan、study-session、content、settings-data 等用户能力。 | 跨 feature 的核心规则副本。            |
| src/domain/study/           | Study Engine、计划骨架、会话状态与纯策略。                                 | React、CSS、Dexie、fetch。             |
| src/domain/questions/       | Question 协议、判题、规范化、类型注册表与 Feedback 数据。                  | 具体页面布局、AI SDK。                 |
| src/domain/learning-events/ | 事件合同、工厂、校验与投影输入。                                           | 画像快照、UI toast。                   |
| src/domain/review/          | ReviewScheduler 端口、FSRS 适配前的领域语义、评分策略。                    | 直接 import ts-fsrs 到页面。           |
| src/domain/profile/         | 事件聚合器、薄弱点与趋势投影。                                             | AI 推断写回。                          |
| src/application/            | 用例、事务编排、ViewModel 映射、错误到 UI 状态的转换。                     | CSS、具体 IndexedDB 表。               |
| src/application/ports/      | Repository、AI、Audio、Clock、ID、Platform 接口。                          | 供应商类型。                           |
| src/infrastructure/db/      | Dexie 数据库、版本、索引、事务、Repository 实现。                          | 学习调度决策。                         |
| src/infrastructure/ai/      | Gateway Client、Prompt Registry、Schema 双检、回退与调用日志。             | 组件和路由。                           |
| src/infrastructure/audio/   | Web Speech、音频资产、缓存与播放器适配。                                   | 题目判定。                             |
| src/infrastructure/pwa/     | Service Worker、缓存清单、更新与离线消息。                                 | LearningEvent 或 FSRS 运算。           |
| src/platform/               | Web 与未来 Capacitor 的通知、震动、文件、生命周期适配。                    | feature 对 window.Capacitor 的判断。   |
| src/ui/                     | Design Token、基础组件、QuestionFrame、AI Bubble、状态样例。               | Repository、AI 调用和领域判断。        |
| src/schemas/                | 跨进程 / 外部输入的版本化运行时 Schema。                                   | 仅供内部编译期使用的零散类型。         |
| src/migration/              | v1 只读读取器、转换器、校验器、报告、staging 编排。                        | v2 日常业务功能。                      |
| src/shared/                 | 无业务含义的少量通用能力，例如结果类型、时间格式。                         | 大而全 utils.ts、types.ts 或常量仓库。 |
| src/test/                   | 固定样例、契约样例、迁移夹具、E2E 支撑。                                   | 生产运行时分支。                       |

## 3.1 依赖方向规则

- domain 只能依赖 domain 内部和无副作用 shared；任何 React、Dexie、HTTP、Web API import 都视为架构违规。

- application 可以依赖 domain 与 ports；不能依赖具体 infrastructure 实现。

- infrastructure 实现 ports，并可依赖外部库；不得反向 import pages 或 features。

- pages / features 通过 application 用例取数和提交意图；ui 组件只接收 props 与语义状态。

- schemas 是外部信任边界；TypeScript 类型不能替代运行时验证。

## 3.2 个人项目的拆分阈值

| 信号                                               | 动作                                                   |
| -------------------------------------------------- | ------------------------------------------------------ |
| 文件同时处理 UI、存储、AI 或算法中的两类以上职责。 | 按层拆分，先抽用例或端口，不先创建通用工具箱。         |
| 同一状态序列在两个组件重复出现。                   | 提升为领域 / 应用状态机；组件只渲染。                  |
| 新增题型需要改页面、会话、统计和 AI 四处 switch。  | 完善 QuestionTypeRegistry 与判别联合；MVP 不新增类型。 |
| 一个 feature 目录只有一个文件。                    | 保持扁平，不为“看起来架构化”提前建空层。               |
| 共享模块只有单一调用方。                           | 留在 feature；第二个真实调用方出现后再上移。           |
| 模块超过约 300–400 行且测试难以隔离。              | 按职责拆分；行数是提示，不是硬性质量指标。             |

# 4. 核心模块设计

核心模块以输入、输出和禁止职责定义边界。模块之间优先传递领域对象、命令与结果，不传 React event、Dexie record、HTTP response 或模型供应商原始对象。

## 4.1 App Shell

| 负责                                                                                 | 输入 / 输出                                                           | 不负责                                         |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------- | ---------------------------------------------- |
| 路由、主题、深色/减少动态、语言上下文、安全区域、顶部/底部导航、全局离线与更新提示。 | 输入：启动状态、User 设置、平台状态；输出：页面容器和全局 ViewModel。 | 学习计划、判题、FSRS、数据库转换、AI 上下文。  |
| 捕获未处理错误并提供恢复入口；会话进行中时协调 PWA 更新提示。                        | 输出：错误页、恢复操作、刷新/更新决策。                               | 吞掉领域错误或把所有错误统一显示为“网络异常”。 |

状态边界 App Shell 的 Zustand store 可以持有主题、连接状态、当前路由摘要和会话 ViewModel；它不能成为 User、Question、LearningEvent 或 ReviewState 的持久化副本。

## 4.2 Study Engine

Study Engine 是每日学习与会话顺序的领域核心。它接收已存在的计划骨架、题目候选和学习状态，输出确定的区块、题目队列、下一步和会话状态；不生成 UI。

| 能力         | MVP 行为                                                                      | 边界                                                    |
| ------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------- |
| 今日计划骨架 | 按时间预算依次装入 FSRS 到期项、近期错项、基础薄弱点和少量新内容。            | AI 只能在配额内建议语境、干扰项与区块内顺序。           |
| 题目队列     | 从已验证题目池选择；缺少 AI 内容时调用模板题目工厂。                          | 不接受 raw AI JSON。                                    |
| 会话状态     | created → active → paused / completed / abandoned；保存当前区块和题目检查点。 | 退出恢复不依赖组件内存。                                |
| 动作处理     | answer、self-rating、hint、audio、skip、next。                                | 每个动作由应用用例写事件；Engine 不直接操作 IndexedDB。 |
| 时长预算     | 基于题数和历史平均用时控制区块上限。                                          | 不追求 AI 动态重排整天课程。                            |

## 4.3 Question System

Question System 把来源不同的题目统一成一个受版本控制的协议，并通过 QuestionTypeRegistry 映射到固定 Answer 原语。MVP 注册 choice 与 text-input；audio 是能力标记和媒体资源，不是第三种页面。

| 子模块            | 职责                                                        | 输出                                     |
| ----------------- | ----------------------------------------------------------- | ---------------------------------------- |
| Question Schema   | 定义协议版本、判别联合和外部输入校验。                      | ValidatedQuestion 或 ValidationFailure。 |
| Question Loader   | 按会话、目标与缓存状态加载已验证题目。                      | 不可变 Question 列表。                   |
| Answer Normalizer | 按语言和题型处理空白、大小写、全半角、假名等已批准规则。    | 标准化答案 + 使用过的规则版本。          |
| Answer Judge      | 确定性比较 optionId 或可接受答案集合。                      | Judgement、正确答案引用、Feedback 数据。 |
| Feedback Builder  | 合并判定、模板解释、词条事实与可选 AI 解释状态。            | 与 UI 无关的 FeedbackModel。             |
| Question Registry | 将 type 映射到 renderer capability、judge 与 event mapper。 | 受支持能力；未知类型拒绝。               |

## 4.4 Learning Event System

LearningEvent 是“发生了什么”的事实日志。事件写入后不可覆盖；需要纠错时追加 correction 事件并引用原事件。删除只允许按明确的数据清理 / 隐私操作执行，不能用于让画像看起来更好。

| 事件策略    | 规则                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 事件粒度    | 提交时用 AnswerSubmitted 汇总实际答案、选项、耗时、提示、重听和修改次数；没有提交的跳过、主动自评等使用独立事件。避免每个按键都写事件。 |
| 顺序与身份  | 事件使用稳定 eventId、occurredAt、sessionId、questionId 与 target reference；同一命令重试必须依赖 idempotencyKey 去重。                 |
| 不可篡改    | 业务层不提供 updateEvent；CorrectionEvent 记录原事件、原因和修正内容。                                                                  |
| 事实 / 推断 | 用户输入、点击、耗时是事实；“容易混淆”“提示依赖高”是 Profile 投影，不能写回原事件。                                                     |
| 迁移边界    | v1 studyRecords、错题汇总和 FSRS 日志按迁移规格保留在对应历史域；不得反造不存在的 v2 LearningEvent。                                    |
| 提交语义    | 事件与 StudySession 检查点在同一事务提交；成功后 UI 才进入已反馈 / 下一题状态。                                                         |

## 4.5 Review Engine

Review Engine 包装 FSRS，输入 ReviewState、评级与时间，输出新的 ReviewState 和必要 ReviewLog。它只回答“何时再复习”，不回答“用户为什么错”“下一题用什么语境”。

- 通过 ReviewScheduler 端口隔离 ts-fsrs；领域和 UI 不直接依赖第三方卡片类型。

- 评分映射策略单独版本化。忘记/模糊/认识、答题正确性、提示等如何映射 Again/Hard/Good/Easy 必须可测试、可追溯，不由 AI 决定。

- v1 迁移卡片是不可重建的 baseline seed；v2 只从该基线继续更新。不得因升级算法而重算历史 due。

- 算法升级先在固定卡片样例上双跑，比较 due、state、reps 与 lapses，再决定是否迁移 ReviewState。

- ReviewState 与 ReviewLog 是调度状态；LearningEvent 仍保留完整行为事实，二者不相互替代。

## 4.6 Learner Profile

LearnerProfile 是可重建的物化投影，不是用户事实表。Profile Projector 按 LearningEvent 顺序消费，并保存聚合版本、算法版本与最后处理游标。

| 聚合组   | MVP 输出                                           | 更新原则                                                  |
| -------- | -------------------------------------------------- | --------------------------------------------------------- |
| 近期错项 | 目标、维度、近 7/30 日错误与连续表现。             | 按事件窗口计算；不永久贴标签。                            |
| 易混淆   | 错误选项 / 输入之间的混淆对，例如 シ/ツ、/ɪ//iː/。 | 达到最小证据门槛才进入摘要；保留计数依据。                |
| 速度     | 按题型和语言的中位/平均耗时。                      | 异常值裁剪策略版本化。                                    |
| 提示依赖 | 有提示作答比例、提示后正确率。                     | 提示是行为，依赖度是投影。                                |
| 重听倾向 | 音频题重听分布与近期趋势。                         | 不把重听解释为能力差；仅用于练习安排。                    |
| 基础技能 | 假名 / IPA 目标的近期稳定度与薄弱点。              | 与 VocabularyItem 共用 target reference，不建第二套引擎。 |

重建规则 Profile 可以从 v2 事件重新投影；迁移的历史聚合如果没有原始事件，只能作为带来源的 baseline snapshot，不能伪装成可逐条解释的新事件。

## 4.7 AI Service

AI Service 是应用层访问模型能力的唯一入口。组件只发起“请求解释”“补充题目”等业务意图；AI Service 负责上下文最小化、任务模板、网关调用、Schema / 语义校验、缓存、超时、重试和回退。

| 负责                                                                                        | 不负责                                        |
| ------------------------------------------------------------------------------------------- | --------------------------------------------- |
| 任务 API：suggestPlan、generateQuestions、explainError、generateExample、summarizeSession。 | 通用聊天代理、页面控制、导航或组件树生成。    |
| Prompt Registry 与版本；模型供应商适配；调用用途、耗时、估算成本与失败原因。                | 保存完整学习历史或将模型推断写成事实。        |
| 服务端与客户端双重结构校验；题目语义检查；内容 hash 去重。                                  | 绕过 Question System 直接把文本显示到答题页。 |
| 网络、额度、超时和解析失败转为明确的 AIResult。                                             | 让 AI 错误升级为整个学习会话错误。            |

## 4.8 Audio Service

Audio Service 把 TTS 请求、播放状态和音频资产分开。MVP 默认使用 BrowserSpeechAdapter；预生成或远程返回的音频 Blob 才进入持久缓存。浏览器 speechSynthesis 没有可缓存音频字节，不能伪称已缓存。[T16]

| 子能力 | MVP                                                                 | 未来                                                    |
| ------ | ------------------------------------------------------------------- | ------------------------------------------------------- |
| TTS    | text + language + rate → BrowserSpeechAdapter；能力检测与语音选择。 | RemoteTTSAdapter 经 AI / Media Gateway 返回可缓存音频。 |
| 播放器 | idle / loading / playing / paused / ended / error；单实例互斥播放。 | 原生音频会话、后台控制。                                |
| 缓存   | 预置音频与下载 Blob 使用版本化 key、大小上限和 LRU。                | 下载课程包与更稳定的跨设备媒体。                        |
| 事件   | 播放、重听、语速和错误由应用用例写 LearningEvent。                  | ASR 结果使用独立 SpeechInputPort，不塞进 AudioOutput。  |
| 降级   | 声音不可用时给出文本路径或允许跳过音频依赖题。                      | 离线语音模型需独立立项。                                |

# 5. 数据架构设计

## 5.1 三层数据原则

| 层   | 代表数据                                    | 可否修改                                        | 如何恢复                                                |
| ---- | ------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------- |
| 事实 | LearningEvent、用户词、设置、迁移原始快照。 | 事件只追加；内容按明确用例修改并留版本 / 时间。 | 从备份或迁移快照恢复。                                  |
| 聚合 | LearnerProfile、近期错项视图、统计。        | 由投影器覆盖更新。                              | 从事件和 baseline snapshot 重建。                       |
| 调度 | ReviewState、ReviewLog、StudyPlan。         | 由版本化规则确定性更新。                        | ReviewState 从迁移 seed + v2 复习轨迹恢复；计划可重建。 |
| 缓存 | 已验证 AI Question、音频、派生 ViewModel。  | 可淘汰。                                        | 在线重新生成或回退模板。                                |

## 5.2 核心实体

| 实体              | 作用                                                       | 主要关系                                                  | 生命周期 / 真相级别                                 |
| ----------------- | ---------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------- |
| User              | 本地学习者设置与首设状态；不是云账号。                     | 拥有当前 Language、StudySession、设置与数据集。           | 首设创建、设置修改；本地事实。                      |
| Language          | ja / en 的规则、显示与内容版本入口。                       | 约束词条、题目、音频和画像。                              | 内置配置，版本化发布。                              |
| VocabularyItem    | 内置词、用户词与 override 合成后的学习内容读模型。         | 被 Question、ReviewState、Event、Folder / Favorite 引用。 | canonical 版本 + 用户事实；稳定 ID。                |
| LearningEvent     | 记录答题、自评、提示、音频与跳过事实。                     | 引用 Session、Question、learning target。                 | 只追加；永久或由明确数据清理策略处理。              |
| ReviewState       | 每个 target + dimension 的 FSRS 活跃状态。                 | 由复习评级更新；产生 ReviewLog。                          | 可变调度快照；算法版本化；迁移 seed 受保护。        |
| LearnerProfile    | 近期薄弱点、速度、提示与重听等聚合。                       | 由 Event Projector 生成；供计划和 AI 摘要读取。           | 可覆盖、可重建的投影。                              |
| Question          | 经过验证、可由固定 UI 渲染的不可变题目。                   | 引用 target；属于 Session；产生 Event。                   | built-in / template / ai；验证后缓存，过期可淘汰。  |
| StudySession      | 一次学习流程的区块、队列、进度和恢复点。                   | 包含 Question refs；聚合 Event；归属于 StudyPlan。        | created → active → paused / completed / abandoned。 |
| StudyPlan         | 某日的规则骨架、预算、区块和来源说明。                     | 生成一个或多个 Session；读取 ReviewState/Profile。        | 按日期版本化；可重建但已开始后冻结主体顺序。        |
| MigrationMetadata | 迁移状态、checkpoint、idMap、计数、报告与 active dataset。 | 关联迁移写入和原始档案。                                  | 长期审计事实；不得被普通清理覆盖。                  |

## 5.3 VocabularyItem 与 learning target

VocabularyItem 不应成为所有学习内容的万能大表。领域协议使用稳定 learningTargetRef：MVP 可指向 vocabulary、kana 或 phoneme；未来 grammar 等类型只有在产品进入相应阶段后注册。Study Engine、ReviewState 与 LearningEvent 只依赖引用和维度，不依赖某一内容表的全部字段。

- 内置词不复制到用户数据表；通过 canonical manifest + BuiltInWordOverride 合成读模型。

- 用户词保留稳定 ID；同名词不自动合并，符合迁移规格的身份规则。

- 日语维度使用 spelling / reading / meaning；英语使用 spelling / listening / meaning。v1 kanji / kana 仅作为迁移 raw 字段。

- 内容版本升级不能修改既有事件的 target identity；失效内容以 tombstone / archived 状态维持引用完整性。

## 5.4 写入与投影一致性

- 应用用例接收命令并完成当前 Question / Session 版本检查。

- 程序判题，构造 LearningEvent 与新的 Session checkpoint。

- 在一个 IndexedDB 事务内追加事件、更新会话检查点，并写入待投影标记 / 游标。

- 事件提交成功后，投影器幂等更新 ReviewState 与 LearnerProfile；中断时从最后游标恢复。

- UI 接收成功结果并显示 Feedback；AI 解释独立异步，不参与事实事务。

实现约束 Dexie 事务中不等待网络、TTS 或模型调用；IndexedDB 事务会在任务空闲后自动提交，外部异步必须放在事务之前或之后。[T08]

## 5.5 ID、版本与保留

| 主题        | 原则                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| ID          | 业务 ID 稳定且与展示文本无关；迁移 ID 使用规格中的确定性映射。Question / Event 可使用生成 ID，但命令重试必须有幂等键。    |
| Schema 版本 | 数据库、Question、LearningEvent、Prompt、Profile 算法、FSRS 适配器、备份和迁移分别版本化，不共用一个模糊 appVersion。     |
| 时间        | 业务逻辑通过 ClockPort；事件保存绝对时间与必要时区 / 本地日期语义。迁移不为 dateOnly 伪造时刻。                           |
| 删除        | 用户内容使用明确删除 / 回收策略；被事件引用的 target 保留 tombstone。事件清理必须是独立隐私功能。                         |
| 缓存        | AI Question、音频和 ViewModel 有配额与 LRU；LearningEvent、ReviewState、迁移报告不按缓存清理。                            |
| 备份        | 导出事实、用户内容、ReviewState、必要日志、设置和迁移元数据；Profile 可重建，SW/HTTP cache、API key 与音频 cache 不导出。 |

# 6. Question Schema 设计

Question Schema 是 AI、模板题、缓存、判题和 UI 之间的正式协议。它使用版本化判别联合：共同 envelope 保持稳定，type 决定 content、answer 与 options 的合法形状。以下是架构级字段，不是完整数据库字段。

## 6.1 基础协议

| 字段组        | 作用                                                                               | MVP 约束                                               |
| ------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------ |
| id            | 题目稳定身份；用于会话、事件、去重与缓存。                                         | 同内容 hash 可复用；不能只用数组索引。                 |
| schemaVersion | 解析与兼容版本。                                                                   | 未知主版本拒绝，不能猜测降级。                         |
| type          | 渲染 / 判题判别键。                                                                | 仅 choice、text-input；其他类型不注册即拒绝。          |
| language      | ja 或 en。                                                                         | 必须与 target 和内容规则一致。                         |
| content       | 题干、刺激材料、必要上下文和展示语义。                                             | 纯数据；禁止 HTML、CSS、布局指令和脚本。               |
| answer        | 程序判题所需的正确 optionId 或可接受答案与规范化策略。                             | 必须可确定性判断；MVP 不包含 AI 评分。                 |
| options       | 选择题的稳定 optionId、label 与必要辅助信息。                                      | choice 必需；答案必须唯一命中；text-input 禁止伪选项。 |
| explanation   | 模板解释、词条事实或已验证 AI 解释引用。                                           | 可缺省；不能作为正确答案唯一来源。                     |
| audio         | TTS 文本 / 资产引用、语言、默认语速与是否必需。                                    | 作为组合能力；失败必须有题目级回退。                   |
| metadata      | target refs、来源、难度、生成 / Prompt / 模型版本、validatorVersion、contentHash。 | 不包含 UI 布局和未经证实的用户事实。                   |

## 6.2 MVP 判别联合

| type       | content                | answer                                | options                       | 渲染原语     |
| ---------- | ---------------------- | ------------------------------------- | ----------------------------- | ------------ |
| choice     | prompt + 可选 stimulus | correctOptionId                       | 2–6 个稳定 optionId；无重复。 | ChoiceAnswer |
| text-input | prompt + 可选 stimulus | acceptedAnswers + normalizationPolicy | 不存在。                      | TextAnswer   |

听力选择、假名辨认和音标辨认都映射到 choice；拼写和假名输入映射到 text-input；audio 只增加刺激输入，不改变提交、判题与 Feedback 状态机。

## 6.3 验证闸门

| 阶段    | 检查                                                              | 失败处理                                    |
| ------- | ----------------------------------------------------------------- | ------------------------------------------- |
| 1. 传输 | HTTP 状态、大小、超时、JSON 可解析。                              | 记录 AI failure；不缓存 raw 为正式题目。    |
| 2. 结构 | Zod / JSON Schema、必需字段、判别联合、未知字段策略。             | Rejected: schema_invalid。                  |
| 3. 语义 | 答案存在、选项不重复、语言一致、audio 可用性、字符串长度。        | Rejected: semantic_invalid。                |
| 4. 事实 | 目标词 / 假名 / 音素来自允许内容；正确答案与 canonical 事实一致。 | Rejected: answer_mismatch。                 |
| 5. 教学 | 难度范围、干扰项合理、无泄题、无未规划题型。                      | Rejected 或降级为人工 / 开发审核。          |
| 6. 去重 | contentHash、近期已用题目、同批相似度。                           | 丢弃重复，补足时使用模板。                  |
| 7. 发布 | 标记 validatedAt、validatorVersion、source。                      | 只有 validated 可进入 Question Repository。 |

硬规则 AI 输出错误时不能“尽量渲染”。未知 type、缺少 answer、答案不在 options、target 不存在或 schemaVersion 不支持时，整题拒绝并回退。

## 6.4 判题与规范化

- choice 只比较 optionId，不比较可变显示文本。

- text-input 的大小写、Unicode NFKC、首尾空白、假名转换等规则必须按语言和题目声明；默认不做过度模糊匹配。

- acceptedAnswers 是受控集合；若存在多个合法答案，全部在题目生成 / 校验阶段确定，提交后不临时询问 AI。

- 显示用户原始输入，同时保存标准化结果和 normalizationPolicyVersion，以便解释与回归。

- MVP 的正确 / 错误结果不可被 AI 解释反转；若发现题目答案错误，题目退役并追加数据修正流程。

## 6.5 未来题型扩展

未来新增 grammar-fill、sentence-order、matching 或 open-response 时，通过 QuestionTypeDefinition 注册 schema、renderer capability、judge、event mapper 与可访问性验收。新增 type 需要一份架构决策和完整契约测试；MVP 不建立空实现。

| 扩展点            | 稳定部分                                           | 新增部分                       |
| ----------------- | -------------------------------------------------- | ------------------------------ |
| Question envelope | id、version、language、metadata、source。          | type 专属 content / answer。   |
| Study Engine      | 队列、进度、暂停、跳过、Feedback 时序。            | 题型完成条件。                 |
| UI                | QuestionFrame、操作区、Feedback、AI Bubble。       | Answer renderer。              |
| 事件              | event envelope、session / question / target refs。 | 题型专属 payload。             |
| 判题              | Judgement 结果协议。                               | 确定性算法或未来 AI 评分适配。 |

# 7. AI 架构设计

## 7.1 架构选择：薄型 AI Gateway

纯 PWA 无法保密模型供应商 API Key；任何发到浏览器的秘密都可以被读取或修改。[T19] 因此 Phase 2 需要一个轻量、无状态 AI Gateway。它不是账号后端或学习数据库，只承担秘密、限额、任务协议和供应商适配。

| 位置           | 职责                                                                              | 不保存 / 不决定                      |
| -------------- | --------------------------------------------------------------------------------- | ------------------------------------ |
| PWA AI Service | 构建最小 TaskContext、调用网关、再次校验、缓存、回退、映射 UI 状态。              | 供应商密钥；全量历史；服务器会话。   |
| AI Gateway     | 服务端密钥、任务白名单、Prompt 版本、模型适配、请求大小 / 频率 / 超时、结构校验。 | 学习事实、FSRS、长期画像、页面状态。 |
| 模型供应商     | 按任务输出候选结构化内容。                                                        | 直接访问用户数据库或 UI。            |

不是服务器集群 Gateway 可以先部署为一个 serverless function / edge function 与少量任务路由；不设计微服务、队列或云数据库。若 AI 尚未启用，Phase 1 完全不需要它。

## 7.2 调用流程

- 应用用例确定 taskType、目标词 / 技能、规则计划位置与允许成本。

- Context Builder 从 LearnerProfile 读取摘要，只选择当前任务所需证据；不发送全量 LearningEvent。

- Prompt Registry 组合任务模板、Question Schema 版本、语言规则、难度和禁止项。

- Gateway 校验请求、应用限额，选择模型适配器并要求结构化 JSON。

- Gateway 执行结构校验；客户端收到后再次执行结构、事实、教学与去重校验。

- ValidatedQuestion 写入 Question Repository；失败使用缓存 / 模板内容并记录 failure reason。

- UI 只从 Question System 取得题目；AI 原始文本永不直接成为答题界面。

## 7.3 任务协议

| 任务              | 输入摘要                                            | 输出                             | MVP 触发                                   |
| ----------------- | --------------------------------------------------- | -------------------------------- | ------------------------------------------ |
| suggestPlan       | 固定计划骨架、区块候选、薄弱点摘要、时间预算。      | 受限排序 / 语境 / 难度建议。     | 每天最多一次或计划重建时；规则可完全替代。 |
| generateQuestions | target facts、允许 type、正确答案约束、干扰项来源。 | 小批量 Question candidate JSON。 | 后台预生成，不逐题调用。                   |
| explainError      | 当前题、用户答案、正确事实、相关近期错误摘要。      | 短解释、对比与可选提示。         | 用户主动请求或高价值重复错项。             |
| generateExample   | target facts、级别、允许语法和语言。                | 例句 + 中文解释候选。            | 按需；必须事实 / 语言检查。                |
| summarizeSession  | 会话结果与 Profile 摘要，不含全量历史。             | 结构化总结要点。                 | Phase 2 可选；模板总结始终存在。           |

## 7.4 降低幻觉与质量风险

| 风险         | 控制                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| 错误答案     | 正确答案优先由 canonical 内容和程序提供；AI 主要生成题干、语境和干扰项。候选 answer 必须与事实库交叉校验。 |
| 格式错误     | 网关约束 JSON Schema；客户端 Zod 再验证；未知字段 / type 策略固定。                                        |
| 难度失控     | 输入允许词表、目标级别、句长和语法边界；超出边界拒绝或降级。                                               |
| 干扰项不合理 | 从真实易混淆集合和词库候选中选；重复、同义多答案、答案泄露检查。                                           |
| 解释自相矛盾 | 解释必须带 correctFact refs；显示时明确“AI 外教”；错误时回退模板。                                         |
| 重复内容     | 按 target + task + promptVersion + contentHash 去重；按小批量缓存。                                        |
| Prompt 漂移  | Prompt Registry 版本化；升级使用固定测试集并比较通过率、正确性和成本。                                     |
| 模型升级     | ModelAdapter 隔离供应商；新模型先 shadow / 离线样例验证，不直接替换生产输出。                              |

## 7.5 AI 不可用时的降级

| 失败           | 用户体验                             | 系统行为                                  |
| -------------- | ------------------------------------ | ----------------------------------------- |
| 离线           | 今日复习继续；AI 按钮显示暂不可用。  | 使用规则计划、内置 / 模板题、模板解释。   |
| 额度用尽       | 不打断当前会话；说明今日 AI 已用完。 | 停止新请求，读取已验证缓存。              |
| 超时 / 5xx     | 短提示，可重试；题目仍可提交。       | 有限重试 + 熔断；记录 provider_error。    |
| 无效 JSON      | 用户看不到坏题。                     | 整题 / 整批拒绝，按有效题数补模板。       |
| 事实校验失败   | 不展示候选解释或题目。               | 记录 answer_mismatch / content_mismatch。 |
| Gateway 不可达 | Phase 1 功能完全可用。               | AI 状态与全局网络状态分开。               |

## 7.6 成本、限额与可观测性

- 按 taskType 设置每日调用数、输入 / 输出长度、批量大小和超时；普通鼓励、进度、统计与固定答案判题禁止调用模型。

- 无账号 MVP 使用安装实例标识 + IP / 网关限流控制成本；它只用于额度和滥用控制，不等同于用户身份或跨设备账户。

- 调用日志只保存 taskType、模型 / Prompt / Schema 版本、耗时、估算 token / 成本、状态、failure reason 和内容 hash；默认不保存完整学习上下文。

- 题目生成优先在会话前小批量完成；同 target / Prompt 版本优先复用缓存，禁止每道题临时请求。

- OWASP 将缺少资源限制视为 API 成本与可用性风险；Gateway 必须限制请求频率、体积、并发和模型预算。[T20]

## 7.7 v1 API Key 冲突处理

推荐决策 迁移规格要求 deepseekApiKey 明文不迁移并记录 requiresReentry。v2 正常模式改用 Gateway 后无需用户重新输入供应商密钥；迁移报告只说明“旧密钥未迁移”。只有未来明确立项 BYOK 模式时，才提供独立的重新输入与安全说明。

# 8. 数据迁移架构

v1 → v2 迁移是独立子系统，不是 Dexie 的普通 schema upgrade，也不与页面重构混写。迁移读取 v1 keyval-store / localStorage 的真实语义，写入全新的 v2 staging dataset；只有全部验证通过后，才切换 activeDatasetId。

## 8.1 迁移组件边界

| 组件                    | 职责                                                                             | 输出                                    |
| ----------------------- | -------------------------------------------------------------------------------- | --------------------------------------- |
| LegacySourceProbe       | 探测 IndexedDB、localStorage、应用版本、备份类型、WebView origin 与双副本分歧。  | SourceInventory；不写 v1。              |
| Snapshotter             | 按迁移规格复制全部原始键、选定备份和 canonical manifest 摘要。                   | 只读 raw snapshot + sourceFingerprint。 |
| LegacyReader            | 复现 v1 的 IndexedDB 优先 / localStorage 回退语义；解析分离词存储与旧 myWordDB。 | 规范化但未关联的 legacy records。       |
| CanonicalIdentityLoader | 加载固定提交的日 / 英 canonical 身份表并验证总数与唯一性。                       | 稳定 identity index。                   |
| Transformer             | 逐域转换 Word、Override、Folder、Mastery、FSRS、历史、设置等。                   | staging records + rawV1Fields。         |
| IdResolver              | 按规格生成 oldRef → newWordId、置信度、冲突、tombstone 与 quarantine。           | 固化 idMap；后续关系不可另算。          |
| MigrationValidator      | 数量守恒、外键、维度、时间、FSRS、幂等复跑和抽样。                               | ValidationReport；P0 阻断提交。         |
| Committer               | 在单一 metadata 事务切换 activeDatasetId / commit marker。                       | COMPLETED 或保持旧 active。             |
| Reporter                | 生成来源、目标、去重、隔离、跳过、冲突和恢复信息。                               | 用户可读迁移报告 + 内部诊断。           |

## 8.2 执行流程

- 预检空间：raw snapshot + staging + 20% 安全余量；不足则零写入退出。

- 冻结 v1 写入，创建完整原始快照；migrationSafetySnapshot_v1 不能替代全量快照。

- 识别 dataSchemaVersion、wordStorageVersion、backupVersion、来源优先级和冲突。

- 加载固定 canonical identity；先迁移 Word / UserWord / BuiltInWordOverride，再固化 idMap。

- 按依赖顺序迁移 Folder / Favorite、Mastery / needsReview、Study、FSRS、Mistake、AI 历史、Recycle、设置。

- 敏感密钥不迁移；Android 通知实例不迁移，只保留设置并在完成后重排。

- 执行规格 V01—V25 的数量、外键、FSRS、幂等与回滚验证；隔离记录逐条可解释。

- 验证通过后切换 activeDatasetId；失败保留 v1、raw snapshot 和 staging 诊断，不部分提交。

## 8.3 迁移状态机

| 状态         | 允许写入                            | 恢复规则                                                       |
| ------------ | ----------------------------------- | -------------------------------------------------------------- |
| NOT_STARTED  | 无。                                | 创建新 migrationId。                                           |
| SNAPSHOTTING | 仅 snapshot 临时区。                | 半快照丢弃并重做。                                             |
| IN_PROGRESS  | 仅当前 migrationId 的 staging。     | 验证 checkpoint digest 后继续；否则清空该 staging 重跑。       |
| VALIDATING   | 仅报告与隔离区。                    | 失败转 FAILED；通过转 COMMITTING。                             |
| COMMITTING   | 仅 active pointer / commit marker。 | 检查 marker；未切换重试，已切换完成。                          |
| COMPLETED    | active v2 数据。                    | 相同 fingerprint + specVersion 返回既有结果，不重复写。        |
| FAILED       | 不写 active。                       | 修复后同 migrationId 重试；保留 v1 与 raw snapshot。           |
| ROLLED_BACK  | 恢复旧 active。                     | 允许重新开始；若 v2 已新增数据，先导出，不在迁移器内自动合并。 |

## 8.4 幂等、原子与回滚

- sourceFingerprint 和 migrationId 完全沿用迁移规格；敏感 key 只加入存在位，不加入明文。

- 每条 staging 记录使用 domain | businessPrimaryKey | migrationId 的幂等键；无天然主键的日志使用内容指纹。

- 迁移转换函数必须是纯函数：相同输入、canonical manifest 与 specVersion 得到相同输出和报告。

- active 数据切换是唯一提交动作；迁移过程中页面不得同时读取部分 v2 表和 v1 表。

- P0：稳定词 ID、英文维度、FSRS、override、来源分歧、空间 / 原子性任一失败都阻断发布。

- 迁移完成后保留 v1 原始数据至少一个稳定版本周期；清理必须在用户确认且已有有效备份后执行。

## 8.5 运行性能

迁移管线按域和固定批次执行，每批写 checkpoint 并让出主线程；纯转换与校验保持 Web Worker 兼容。如果真实设备测量显示首屏阻塞，再把执行器移入 Worker，接口与数据规则不变。迁移期间 UI 只展示进度、空间不足、失败项和恢复操作，不承载转换逻辑。

不可混淆 v1 历史数据迁移与 v2 IndexedDB 未来 schema upgrade 是两套机制：前者读取旧应用事实并可回滚；后者只处理已进入 v2 的受控结构升级。

# 9. 离线与 PWA 架构

## 9.1 离线能力矩阵

| 能力                  | 离线状态                                         | 依赖                                     |
| --------------------- | ------------------------------------------------ | ---------------------------------------- |
| App Shell / 六页面    | 可打开。                                         | 预缓存静态资源与 manifest。              |
| 已下载词库 / 基础内容 | 可搜索、浏览和用于题目。                         | 版本化内容资产 + IndexedDB 引用。        |
| 今日规则计划          | 可生成。                                         | ReviewState、Profile、模板题与本地时间。 |
| FSRS                  | 完整可用。                                       | 本地 ReviewState / ReviewLog。           |
| 选择 / 输入题         | 完整可用。                                       | 已验证题目或模板题。                     |
| LearningEvent         | 本地立即写入。                                   | IndexedDB；无“等待同步”状态。            |
| TTS                   | 设备 Web Speech 可用时可朗读；预下载音频可播放。 | 浏览器 voice 或音频缓存。                |
| AI 生成 / 解释        | 不可新调用。                                     | 使用已验证缓存、模板解释和规则回退。     |
| 账号同步              | 不存在。                                         | MVP 不实现。                             |

## 9.2 存储与缓存分域

| 存储              | 保存                                                                            | 策略                                               |
| ----------------- | ------------------------------------------------------------------------------- | -------------------------------------------------- |
| IndexedDB / Dexie | 用户事实、事件、ReviewState、Profile、Session、validated Question、迁移元数据。 | 业务主库；事务、索引、备份、配额监测。             |
| Cache Storage     | App Shell、版本化静态内容、下载音频与网络响应。                                 | 由 Service Worker 管理；可清理，不能作为业务真相。 |
| LocalStorage      | 主题首屏 / 极小启动标记。                                                       | 同步读取仅为防闪烁；启动后以设置 Repository 校正。 |
| Memory            | 当前组件状态、播放器句柄、临时 AI 请求。                                        | 刷新可丢；需要恢复的会话必须写 IndexedDB。         |

## 9.3 Service Worker 职责

| 资源 / 请求                | 缓存策略                                      | 说明                                                                         |
| -------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------- |
| HTML navigation            | NetworkFirst + precached App Shell fallback。 | 保持可更新；离线仍进入 SPA。                                                 |
| 带 hash 的 JS / CSS / icon | Precache / CacheFirst。                       | 构建版本不可变；激活后清理旧 cache。                                         |
| 版本化词库 / 基础资源      | CacheFirst；URL 含内容版本。                  | 新版本通过 manifest 切换，避免半包。                                         |
| 音频 Blob / 文件           | CacheFirst + 大小上限 + LRU。                 | 只缓存可重放二进制；Web Speech 无字节缓存。                                  |
| AI Gateway                 | NetworkOnly。                                 | 个性化请求不由 SW HTTP cache；有效结果由 AI Service 写 Question Repository。 |
| 备份 / 导入                | 不缓存。                                      | 使用 FilePort 与显式用户操作。                                               |

Service Worker 本质是网络代理，可提供离线优先体验 [T12]；它不得直接写 LearningEvent、计算 FSRS、生成 Profile 或保存供应商密钥。

## 9.4 更新策略

- 使用 vite-plugin-pwa injectManifest 保留一个小型自定义 SW；只实现预缓存、运行时缓存、离线导航和更新消息。[T11]

- 新版本下载后采用“提示更新”，不在 active StudySession 中强制 skipWaiting；用户完成 / 暂停后再激活。

- 应用代码版本与数据库 schema 兼容窗口至少覆盖旧 SW 仍控制一个页面周期的场景。

- 更新激活时只清理旧 HTTP cache；不得清理 IndexedDB 或迁移 snapshot。

- 离线提示非阻断，AI 离线状态与整个 App 离线状态分开显示。

## 9.5 配额与持久化

- 首次完成学习或导入数据后请求 navigator.storage.persist()；浏览器可能拒绝，UI 需说明并保留备份入口。[T14]

- 使用 navigator.storage.estimate() 监测 usage / quota；迁移和音频下载前预检空间。

- AI Question 和音频设置独立上限与 LRU；清理优先顺序为临时 ViewModel → AI cache → 音频 → 旧静态 cache，绝不自动删除学习事实。

- PWA 存储仍可能被用户清除；“本地优先”不等于“永不丢失”，备份与迁移报告必须可达。

# 10. Android 扩展路线

当前目标仍是 Web PWA。为了以后用 Capacitor 包装，所有原生能力从第一天起通过 Platform Ports 暴露；Web adapter 提供现有能力，Capacitor adapter 在 Phase 3 逐项替换。Capacitor 的插件本身就是 JavaScript 与原生 API 的跨平台桥接。[T17][T18]

## 10.1 平台端口

| Port                   | Web / PWA 实现                                 | Capacitor 实现             | 领域调用方                             |
| ---------------------- | ---------------------------------------------- | -------------------------- | -------------------------------------- |
| NotificationPort       | Web Notifications / 不支持时关闭。             | Local Notifications。      | Reminder use case；FSRS 不直接调插件。 |
| HapticsPort            | navigator.vibrate 能力检测。                   | Haptics plugin。           | UI feedback use case；受用户设置控制。 |
| FilePort               | File System Access / input download fallback。 | Filesystem / Share。       | 备份、恢复、迁移导入。                 |
| AppLifecyclePort       | visibilitychange / pagehide。                  | App state events。         | 会话 checkpoint 与音频暂停。           |
| AudioOutputPort        | Web Speech / HTMLAudioElement。                | 原生音频或同 Web adapter。 | Audio Service。                        |
| StorageDiagnosticsPort | StorageManager estimate / persist。            | 设备空间诊断适配。         | 迁移、下载与设置页。                   |

## 10.2 避免未来迁移困难

- feature 中禁止 import Capacitor 包或判断运行平台；只注入 Port 实现。

- 通知业务先生成 ReminderPlan，再由 NotificationPort 排程；迁移后重新生成，不迁移操作系统通知实例。

- 文件导入 / 导出使用流或 Blob 语义，不在领域层使用 file://、content:// 或 DOM input。

- 安全区域、软键盘和可见性由 App Shell / Design Token 处理，学习组件不硬编码设备尺寸。

- 数据库通过 Repository 隔离。即使未来评估原生 SQLite，也替换适配器和迁移层，不重写 Study Engine。

- 深链、返回键、前后台切换先由 AppLifecyclePort 统一映射，再进入应用用例。

## 10.3 扩展阶段

| 阶段              | 工作                                                                       | 进入条件                                     |
| ----------------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| A. PWA            | Web adapter、manifest、SW、离线、备份、响应式与安全区域。                  | MVP 默认形态。                               |
| B. Capacitor 包装 | 建立 Android shell、复用同一构建产物、验证 IndexedDB / origin 与升级保留。 | PWA 闭环稳定且确有安装 / 通知需求。          |
| C. 原生能力       | 通知、震动、文件、生命周期逐 Port 替换。                                   | 每项有独立价值与兼容测试。                   |
| D. 数据适配评估   | 只在真实性能 / 容量证据下评估 SQLite。                                     | IndexedDB 已有可复现瓶颈；迁移路径完成演练。 |

# 11. 安全设计

## 11.1 信任边界

| 边界 / 风险    | 控制                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 模型 API Key   | 只存在 Gateway 的服务端秘密环境；不打包进 PWA、不进 IndexedDB、日志或备份。客户端秘密可以被读取，不能靠混淆保护。[T19]    |
| AI 输出        | 一律视为不可信输入；JSON / 语义双检；content 禁 HTML / CSS / script；解释按纯文本 / 受控富文本渲染。                      |
| 学习数据隐私   | 默认只在设备；AI 请求使用最小上下文；Gateway 默认不保存全文，不发送全量事件。                                             |
| 本地存储       | 不声称浏览器存储具备保密性；同设备用户 / 恶意脚本可能读取。API key、token 和秘密不得存业务 DB。[T22]                      |
| 备份文件       | 显式用户操作；带格式版本、内容摘要和完整性 hash；排除 API key、SW cache 与音频 cache；导入先校验再 staging。              |
| AI 滥用 / 成本 | 安装实例 + IP 限流、任务白名单、请求体 / 输出 / 并发 / 每日额度、429 与熔断。[T20][T21]                                   |
| XSS / 供应链   | 严格 CSP、禁止 inline script / eval、限制 connect-src、依赖锁文件与定期升级；AI 文本不使用 dangerouslySetInnerHTML。[T23] |
| 错误与日志     | 用户错误不含 raw provider 响应、Prompt、API key 或完整学习上下文；开发日志按用途最小化。                                  |

## 11.2 AI Gateway 安全

- 只开放列入 Task Registry 的端点，不提供可传任意 prompt / model 的通用代理。

- 校验 Content-Type、Schema、请求大小、语言、target 数量和字符串长度；拒绝外部 URL、工具调用和模型自定义指令。

- 供应商凭据按环境隔离，可轮换；错误响应不回显密钥、上游 header 或内部 Prompt。

- 匿名安装令牌只能标识额度桶，不作为高价值授权。未来账号上线前，不建立“该令牌证明用户身份”的假设。

- 超时、最大输出、并发与熔断在 Gateway 强制执行，客户端限额只是体验层。

## 11.3 本地数据与备份

MVP 的本地数据目标是完整性与可恢复性，不承诺设备被攻破后的机密性。若未来备份需要通过不可信渠道传输，可增加用户口令驱动的加密导出；这不是 Phase 1 闭环的上线阻塞项。无论是否加密，恢复都先进入 staging，并执行 Schema、版本、数量与外键验证。

安全底线 任何为了“省一个网关”而把第三方模型密钥写进前端、LocalStorage、IndexedDB 或备份的方案，均不符合本架构。

# 12. 开发阶段规划

开发顺序按风险和可验证闭环排序：先冻结契约，再让规则学习离线运行，最后接入 AI。每个阶段以行为验收结束，不以“页面写完”作为完成标准。

## Phase 0：工程初始化与契约冻结

| 目标                         | 模块 / 工作                                                                                | 完成标准                                                                 |

## 12.1 推荐纵向开发顺序

- 日语：迁移一个 v1 词条 → 读取 FSRS 到期 → 选择 / 输入 → LearningEvent → 次日计划。

- 日语：加入假名 target 与 audio，证明不需要第二套学习引擎。

- 英语：复用同一链路，验证 spelling / listening / meaning 与 IPA target。

- 离线与备份：断网、刷新、升级、空间不足和恢复演练。

- AI：先 generateQuestions 固定样例，再真实 Gateway；最后接解释和总结。

- Android：只在 PWA MVP 验证后接 Platform adapters。

# 13.《钟日 v2 推荐技术架构》

一句话总结 用 React/Vite 承载固定界面，用纯 TypeScript 学习核心决定流程，用 IndexedDB 保存事实和调度，用投影生成画像，用薄型 AI Gateway 提供可验证的结构化增强；任何外部能力失败都不能破坏基础学习闭环。

## 13.1 推荐技术栈

| 层          | 推荐                                                          |
| ----------- | ------------------------------------------------------------- |
| 界面        | React 19.2 系列、React Router、Design System CSS Variables。  |
| 构建 / PWA  | Vite 8、vite-plugin-pwa、Workbox injectManifest。             |
| 语言 / 校验 | TypeScript strict、Zod、版本化 JSON Schema。                  |
| 状态        | 局部 React state + Zustand 短生命周期 ViewModel。             |
| 领域        | 纯 TypeScript Study / Question / Event / Review / Profile。   |
| 数据        | Dexie / IndexedDB；Repository；本地优先；版本化备份。         |
| 复习        | ts-fsrs 通过 ReviewScheduler 适配并固定算法版本。             |
| AI          | PWA AI Service + 薄型 Gateway + Provider Adapter + 双重校验。 |
| 平台        | Web adapters；未来 Capacitor adapters。                       |
| 测试        | Vitest、Testing Library、Playwright、迁移固定夹具。           |

## 13.2 核心模块与数据流

UI → Application Use Case → Study / Question Engine → 事务写 LearningEvent + Session checkpoint → Profile / Review 投影 → 规则 Today Plan → 可选 AI Task → Schema / 事实校验 → Question Repository → 固定 Question UI。

- 事实不会被 AI 覆盖；画像可以重建；FSRS 只负责到期调度。

- 组件不调用 AI / DB；Service Worker 不写业务数据；迁移器不参与日常运行。

- Question 不通过验证就不存在于用户流程；MVP 固定答案不由 AI 判定。

- Phase 1 离线成立，Phase 2 只增加相关性与解释，不制造单点故障。

## 13.3 主要风险与控制

| 风险               | 最早信号                                   | 控制                                                      |
| ------------------ | ------------------------------------------ | --------------------------------------------------------- |
| 架构过度           | 大量空目录、接口与无调用实现。             | 按纵向切片创建；只为当前真实依赖抽 Port。                 |
| 领域 / UI 再次耦合 | 组件 import Dexie、ts-fsrs 或 AI client。  | 依赖规则、代码评审、domain 单测无浏览器环境。             |
| 事件失控           | 同一行为多种事件语义、画像无法重建。       | 事件字典、版本、幂等键、固定回放样例。                    |
| AI 错题进入学习    | 无效答案、未知 type 在 UI 出现。           | 双重 Schema + 事实校验 + reject-by-default + 模板回退。   |
| API 成本失控       | 逐题请求、重复生成、网关 5xx / 429 上升。  | 批量、缓存、限额、熔断、调用元数据。                      |
| 迁移破坏连续性     | 数量不守恒、FSRS due 改变、override 丢失。 | raw snapshot、staging、V01—V25、P0 阻断、active pointer。 |
| PWA 数据被清理     | quota 接近、persist 未授予。               | Storage diagnostics、备份、缓存 LRU、不误删事实。         |
| 原生锁定           | feature 直接使用 Capacitor / file URL。    | Platform Ports 与 Web / native adapters。                 |

## 13.4 架构变更门槛

以下变化必须新增 ADR 并说明替代方案、迁移、回滚和 MVP 影响：更换前端框架或数据库；新增 Question type；修改 LearningEvent 语义；升级 FSRS 主算法；让 AI 参与固定答案判定；加入账号同步；从 PWA 切换原生存储；修改 v1 迁移身份规则。

最终原则 长期可维护不等于提前设计所有未来。钟日 v2 只稳定那些会跨越页面和版本的边界：事实、协议、调度、迁移、平台端口与 AI 闸门；其余实现保持简单并允许替换。
